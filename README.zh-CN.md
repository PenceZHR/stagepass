## 一 · 这是什么，为什么停

StagePass 想做一台**给单人用的 AI 项目流程仪器**：一个 Change 走八个阶段，
每阶段有判据单，模型填证据、人裁决，两轨互盲，闸门挡住不该过的东西。

**停止不是因为做不下去，是评估之后决定不做。**四条证据：

1. **核心机制已被商品化。**「证据与判决分离」「local-first」「只追加」
   在 [ProjectMem](https://arxiv.org/pdf/2606.12329)（2026-06）里已经是论文；
   「session 结束自动总结落 markdown」有 clerk 等一批工具；
   前置约束那一片被 Kiro（2026-05 国际版）和 GitHub Spec Kit（9.3 万星）占满。
2. **剩下的差异只是一个观点**（档案给人读、稀疏即权重），不是技术。
3. **价值不需要软件。**它真正起作用的部分是人的判断，而人的判断不需要插件——
   两个文本文件就够。
4. **想自动化掉的那一步，恰好是不能自动化的那一步**（见 §三·4）。

## 三 · 被证伪的假设

### 1. 「无人值守」可行

**它和「每轮我都要知情」在逻辑上互为否定。**那 2298 行执行通道
（`plugin/runtime` + `seats` + `await-turn` + `codex/app-server-*` + `stream-state`）
是同时满足两个互斥目标的价钱。删掉之后审批、可见性、可介入、durability
**全都天然成立**——不是被修好了，是矛盾消失时为它建的机械整体作废。

> 复用的检查：**建之前把目标列出来，看有没有两条在互相否定。**五分钟，能省两千行。

### 2. 阶段闸门能挡住人

跟自己的「三作者」模型直接矛盾——闸门让代码的判断凌驾于人。而且交出执行通道之后
本来就拦不住任何事：能"拦"的只有自己面板里的一个状态字段，而面板是自己的。

**闸门该降成体检（linter，非门卫）：出报告，不出判决。**

### 3. 「两轨互盲」是 TDD 的原则

不是。**TDD 按构造就是单作者的**，它分的是时间不是视角。互盲在原始方法论里
存在于**客户验收测试**那一层（XP / FIT），行业留下了 TDD，丢掉了那一层。

而且互盲救不了这个项目实际踩的两个坑（见 §五·2）——那两次是**现实接触**失败，
不是解读分歧失败。

### 4. 全流程自动化只是"模型还不够强"

**是结构性的。**需求不是先存在然后被传达的，**需求是在你看见产出的那一刻才成形的**。
所以循环里必须有人，而且在中间不在两头。

作用域：需求在开工前完全已知的活（编译、转译、按明确规则迁移、实现写死的协议）
可以全自动。做产品不属于那一类。

### 5. 「没人做 = 没人想到」

**空缺不可解读。**它同时兼容"没人想到""试过不行""刚好还没轮到"，
从空缺本身没法分辨。

> 复用的检查：**别搜「有没有人做 X」（得到空缺），搜「谁在做相邻的事、他们怎么做」（得到存在）。**
> 存在是可读的：别人的限制章节直接告诉你他们撞到了什么。

## 四 · 技术实测清单

**这一节是这个仓库对别人唯一还有价值的部分。**全部是真机撞出来的，
公开资料里基本没有。版本标注处为实测版本，之后可能已变。

### Codex · 线程与子 Agent

- **子 Agent 是 fork 父线程的全部历史来的**，不是从零开始。所以"每轮新反方从零怀疑"
  只在跨阶段成立，同一线程内造不出这个条件。
- **子 Agent 线程拒绝外部输入**（0.146.0 正式版）：不能直接 resume 驱动，和父线程活不活着无关。
- **两个 spawn 入口，只有一个设 `agent_path`**：原生 `spawn_agent({task_name})` 才设，
  而它**不是每个会话都有**——没有时整轮作废。
- **spawn 失败是静默的**：主 Agent 会替子 Agent 编答案，turn 照样"成功"。
- **`thread/list` 没有 title**，且看不见零轮次线程。认线程只能靠
  `preview` + `parent_thread_id`（rollout 里 76/76 有值）。
- **UUIDv7 绝不能前缀匹配**——同毫秒生成的线程前缀相同。
- **子 Agent 只继承全局 `config.toml` 的 MCP**，不继承命令行 `-c`。

### Codex · 会话与许可

- **每轮都要按一次 MCP 许可**，而且**按会话算不是按线程**。没人按就静默烧满 30 分钟——
  这一条直接挡死"无人值守"。
- **没被信任的目录会静默等满超时**，判据是 **git 根**，不是 cwd 也不是祖先。
- **Codex 会归档绑着的线程**：`codex resume` 一起来就退，表现是"点了报错"。
  解药 `codex unarchive`；而**那个刚起来就死的 pty，最后一句话看不到**。
- **非订阅连接可以驱动 `turn/start`**。

### Codex · MCP 与 UI

- **elicitation 三条静默坑**：字段**按名字排序**（不是你定义的顺序）、
  **`required` 是硬闸门**（可以拿来当真闸门用）、**空文本格吃掉回车**（而只有最后一格能提交）。
- **Codex App 会渲染 MCP 资源里的 HTML**（`openai/outputTemplate` + `resources/read`，
  特性开关叫 `enable_mcp_apps`）——整套 UI 进 Codex 的可行路径。
  实测于 codex-cli 0.147.0 / App 0.148.0-alpha.15。
- **但 widget 宽度上限约 700px**，且 iframe 外部源被沙箱挡——面板要打包成资源本身。
  "全屏"实为右侧面板标签页（687px，比 inline 还窄）。
- **app-server 公开 JSON-RPC 能从外部开一条真会话**，9.3 秒跑完一轮，
  和 App 自己开的同为 `source=vscode`。
- **可以驱动原生 Terminal 里的 codex TUI**：送题面/关窗/重连全通；
  绑目录不绑 thread id；**回车要单独送**，把手用 tty。

### Claude Code

- **钩子 deny / Stop 都真拦得住**——但**只守得住状态迁移，守写操作会被 Bash 绕过**。
- **`claude` CLI 子进程无法登录**（沙箱内外都是）。
- 会话 id 可指定；子 Agent 在目录里；elicitation 能力已确认。

### 本机环境（可能只对这台机器成立）

- **`preview_start` 起不来面板**：spawn 出的进程 cwd 是 `/` 且 `getcwd` 被拒
  （`EPERM: uv_cwd`），三种 `runtimeExecutable` 都挂在同一处。
  绕过：后台 Bash 起进程 + `preview_start({url})`，或 launch.json 写成**只挂载不 spawn**。
- **面板必须从真终端起**：Run 按钮起的面板 spawn codex 必 EPERM 秒死。
- **沙箱里 curl 连不上 localhost 且静默返回空**——别拿它判断服务起没起。

## 五 · 判断错在哪（机制层面）

### 1. 把需求当结论，而不是赌注

写了 PRD、spec、架构、判据单——**想得不少**。但它们都是以断言形式写的
（「系统应当……」），里面没有一句是「我现在相信 X，而我会这样发现它是错的」。

**所以那个需求可以错两个月，而没有任何一个时刻会告诉你它错了。**

不是没想，是想完之后关掉了发现自己想错的通道。

### 2. 把探索期用收敛期的方式过了

写文档不是探索，**写文档是把猜测格式化**——它一个新信息都不产生，
但它感觉像在推进，因为有产出物。

真实原因是**反馈不对称**：写测试绿了有即时确认，写文档页数涨了有即时确认，
而"想需求对不对"没有任何信号。人会本能地逃向发信号的地方。

> 所以"以后要重视探索期"这个决心会失败——它是意志力对抗梯度。
> **解法是给探索期造反馈**，而不是加强决心。

### 3. 绿色测试证明的是自洽，不是正确

两次代价最大的事故：

- **1177 条全绿，而 MCP 通道断了一夜**——每个替身都在模拟一个已经不存在的工具
- **1137 条全绿，而整张星图从没渲染过**——前端"测试"全是对源码的正则 grep

**这两次互盲也救不了**：一个盲写的测试作者照样会 stub 同一个不存在的工具，
照样会写正则。它们是**现实接触**失败，不是解读分歧失败。

### 4. 在探索之前定了流程架构

为一个自己还没真正过过的工作方式，先建了工具。而自己后来写下的原则说：
**架构的信息只能由建造产生，开工即定架构在信息论上不成立。**
