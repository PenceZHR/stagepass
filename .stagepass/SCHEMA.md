# 结构化输出 · schema

> 存储 JSONL，呈现靠 `sp` 渲染。**存储要可靠解析，呈现要人读，两者不必是同一个文件。**
>
> 判据：**解析失败是静默的** —— 漏一条否决，模型照样提那个方案，而你不知道。
> 所以不用 markdown 管道分隔（内容里出现 `|` 就崩），不用 JSON（不是 append-only 的）。
>
> 中文一律 `ensure_ascii=False` 落盘，`grep` 撞得上。

---

## sessions.jsonl —— 一行一个 session

```json
{
  "id": "sess-0042",
  "at": "2026-08-19T11:20:00+08:00",
  "intent": "实现 X",
  "said": "原话，原样粘贴。不总结不润色。",
  "result": "成 | 部分 | 没成 | 没测",
  "commits": ["a1b2c3d", "e4f5g6h"],
  "logs": ["log-0007"]
}
```

- `intent` —— `sp_begin` 时给。**不必在 session 开头调**，知道要做什么了才调
- `said` —— 不可重导的那部分。**必产**
- `result` —— **必产**（关闭时才填）。`没测` 是合法值，而且连续多个 `没测` 是警报
- `commits` —— **代码从 git 抓，不许模型报**。关闭时快照，之后不变
- `logs` —— 这个 session 产出了哪几条。**大部分是 `[]`，这是对的**

## log.jsonl —— 一行一条学习

两种形状，`kind` 区分。

```json
{
  "id": "log-0007",
  "kind": "假设死了",
  "hits": ["sess-0012", "sess-0031"],
  "believed": "parser 能复用",
  "actual":   "它假设了单行输入",
  "how":      "重构 tokenizer 时才发现",
  "author":   "human | drafted-edited | drafted-accepted",
  "overturned_by": null
}
```

```json
{
  "id": "log-0008",
  "kind": "否掉了",
  "hits": ["sess-0019"],
  "considered": "用 SQLite 做真相源",
  "chose":      "文件优先",
  "because":    "审计物不该只活在一个 sqlite 里",
  "overturned_by": null
}
```

### author —— 模型可以拟稿，但必须说得出是谁写的

模型**可以**先拟两行，人改了再确认 —— 空白字段在疲劳时产出零，而零是最糟的结果
（静默，你事后连「那天有东西没记」都不知道）。而且识别比回忆容易：一个稍微写错的
草稿会让你立刻反应「不对，是……」，那个「不对」正是要记的东西。

**近似的条目严格优于没有条目** —— 对「别再提我否掉的方案」这个用例，
一条大致对的判决照样挡得住重提。

原则不是「不许模型写」，是 **[[三作者]]：每个字段说得出作者**。所以：

```
"author": "human"             人从空白写的
          "drafted-edited"    模型拟的，人改过
          "drafted-accepted"  模型拟的，人一个字没改
```

**这个字段由代码判，不是模型自报** —— 比较提交文本和草稿文本即可，纯机械。

用法两层：**注入时三种都用**（近似的照样管用）；**回看时可信度分层**，
你知道哪条是自己写的、哪条是点过去的。

> 如果 `drafted-accepted` 占比很高，那本身是一条该记的东西 ——
> 说明卡片来得太频，或者你太累。

### 卡片：只在 session 结束时弹一次

**中途不打断。**曾经设计过中途触发（同一文件改三次、说了「不对」、删掉刚写的）——
**那几个信号选错了**：它们在真实开发里一直在发生，是「正常工作探测器」不是
「惊讶探测器」。一下午弹七八次，第三次起就被无脑点掉。

原则性的理由：**惊讶只有回头看才认得出。**改第三次 parser 的当下你以为在调 bug，
只有 session 快结束、看得见整个形状时那条才浮出来。中途打断是在要求你识别一个
自己还站在里面的事件。

> 注意别把这条和「总结是回忆」搞混 —— 那条是对着阶段末尾的 `HANDOFF`（隔了很久）说的。
> **session 末尾事情几分钟前刚发生，transcript 还在上下文里，那还是现场。**
> 空洞从小时和天开始，不从分钟开始。

### 卡片的两条硬约束

1. **线索在字段外，字段里是草稿** —— 「你今天改了 parser 三次」是让你想起来的，
   不是内容的一部分
2. **`不记` 要和 `记下` 一样便宜** —— 跳过比记录麻烦的话，你会为省事随手记垃圾。
   代价不对称的地方，人往便宜那边跑，不往对的那边跑

### 两个触发点，不是一个

**session 结束的时刻不可靠** —— 上下文烧完、直接关终端，Stop 钩子不一定跑得到。

```
session 结束     尽力而为（CC：Stop 钩子）
下次 sp_begin    兜底：「上一个 session 没归档」
```

漏了不会静默，只会延迟一轮。兜底时 transcript 没了但 git 还在。

### 人可以随时主动记，不需要卡片

```
你：「记一条：以为 parser 能复用，其实它假设了单行输入」
→ 模型调 sp_log 装配、分配 id、挂 session。author = human
```

**不对称是对的：你能随时打断它，它不能随时打断你。**

### hits —— 取代 `×N`

`N = len(hits)`。**数组比计数好**：它保留了是哪几次撞上的，能跳回现场。

再撞上同一件事：**不新起一条**，往 `hits` 追加 session id。

### overturned_by —— 被后来的 session 推翻

```json
"overturned_by": {"at": "sess-0040", "why": "parser 是对的，问题在 tokenizer"}
```

**不删、不改原文。**只加这个字段。三个领域给的是同一个答案：会计红冲、event sourcing 补偿事件、git revert —— 都是追加抵消项，不动原始记录。

> **`hits` 和 `overturned_by` 是相反的关系，绝不能混：**
> `hits` 变长 = 这个坑又踩了一次 → **信心升**
> `overturned_by` 非空 = 这条不成立了 → **信心毁**
>
> 混了的话，一条反复被修正的信念会看起来像一条反复被确认的信念 —— 正好是反的。
> 排序和注入必须分开处理。

### 注入规则

`sp_begin` 只注入 **活的头部**（`overturned_by == null`）。被推翻的整条链留着，`sp find` 查得到 ——
**「我以为 A → 不是 A → 其实还是 A」记的是你误解的形状，是最不可重导的一类。**

## boundaries.jsonl —— 一行一次修订

**不改，只追加修订。当前态 = 每个 `id` 的最后一行。改动次数 = 该 id 的行数。**

```json
{"id": "bnd-003", "at": "sess-0012", "line": "parser ↔ tokenizer",
 "where": "谁负责切行", "why": "parser 假设了单行输入，切行必须在它上游"}
```

改动次数是最有价值的一列：**改过 3 次以上的线是真边界**（收敛期冻结时特别小心）；
**一次没改过的，多半你从没真正测试过它**。

## bets.jsonl —— 一行一次状态变化

```json
{"id": "bet-001", "at": "sess-0003", "state": "高危 | 已验 | 已死",
 "text": "×N 在 200 条时的信号会比 20 条时更清晰",
 "killed_by": "log-0007"}
```

`killed_by` 让赌注单可审计，并接回 `log.jsonl`。

## 四条不变量

1. **只有 `hits` 和 `overturned_by` 允许就地改，其余一律追加。**原文一个字节不动
2. **`commits` 由代码从 git 抓**，模型报的会漏会美化
3. **`logs` 为 `[]` 是正常的**，大部分 session 不产生学习
4. **`session` 是地址，没有生命周期**（那天你确实这么说了，永远为真）；
   **`log` 条目是断言，有生命周期**（活着 → 被推翻）。两件事，别合并

---

## 一个要说明的

这是 event sourcing 的存储形态，和 ProjectMem 那类一样。

**但差异从来不在存储上**，在两处：
**内容全部由人产出**（模型只导航和装配），以及**稀疏**（大部分 session 零产出，而稀疏本身就是权重）。
换成 JSONL 不影响这两条。
