## 一、H 档：三块已落

### 1. 真解析器（`graph/module-graph.ts`）

AST 解析，边分五种（值 / 类型 / 副作用 / 动态 / 再导出），指向图外的边记进
`unresolved` —— 一张自称完整的残图比没有图更糟，对账会把缺口读成「这里没有依赖」。
纯模块：进来 `{path,text}`、出去一张图。

**换护栏之前先做了对照，结果必须照实说**：真解析器和正则**在今天这棵树上逐条
一致**（48 模块 152 边、0 差异、0 落空）。所以理由**不是**「正则算错了」，是
**它明天会算错而没人知道** —— 树里恰好没有副作用 import、没有动态 import、
注释里也没有假的 `from "./x"`，三样任何一样出现，正则都会静默给出错的图。

分层护栏和闭包护栏都改读真图，正则那份实现删了。

### 2. 配料单（`graph/ingredients.ts`）

§5.4.1 那个机关：自己完整正文 + 依赖**只给签名** + 谁依赖你 + 全局约束。
看不见实现，就写不出依赖实现细节的代码 —— 不是概率上更难，是物理上做不到。

真树收益（49 模块 / 502 KB）：

```
domain/gap.ts               3.6%   28×
domain/journey.ts           3.7%   27×
work/round-turn-runner.ts   6.4%   16×
web/panel-server.ts        29.0%    3×   ← 自己正文 94.6 KB、牵 33 个依赖
```

**收益和「树拆得好不好」成正比。** J 批因此不只是好看。
（这不是 §5.7 那个 72×：那个比的是「上游文档全量 vs 配料单」，两个数不是一回事。）

### 3. 对账机器（`graph/reconcile.ts`）

六类发现：概念无归宿 / 概念散落 / 模块承载太多概念（「该拆了」的机械判据）/
模块说不出服务谁（§5.2）/ 宏观有关系微观没依赖（最危险）/ 微观有依赖宏观没关系。

**它不生产概念图，只消费**（§5.8·1），**也不判红**（§5.8·6：概念划分是主观的）。

一处设计修正：两头有一头没人承载时不报「关系没实现」—— 那时它和「概念无归宿」
说的是同一件事，而一个不存在的概念会让它的每条关系各报一遍。**对账的价值在于
人愿意读完它。**

## 三、这一趟真正学到的：三次「打开真东西看一眼」

887 条测试和严格类型检查一次都没红过，而下面三样全是看真产出才发现的：

1. **配料单泄漏实现** —— 签名用 `getText()` 取，它把花括号里的注释一起带出来。
   `ChangeState` 成员上十几行讲不变量和历史的 JSDoc 整段漏进了配料单，而这个
   机关的全部价值就是**看不见实现**。改用 `removeComments` 打印器，18.7→13.2 KB。
   **护栏得放在真树上** —— 玩具夹具的注释太干净，测不出这个。
2. **`export export type …`** —— 同一处 `getText()` 把节点自己的 `export` 也带上了。
3. **配料单在玩具夹具上比全树还大**（832 vs 664）—— 样板占大头。那不是设计问题，
   是**尺度问题**：72× 那种数只有真树量得出来。测试因此改成只钉语义，长度那一半
   搬到真树护栏上。

> 前一份交接记的是「UI 三版返工」，这一份记的是「三次看真产出」。**同一条教训
> 的第二种形状：绿灯只证明你问过的问题。**
