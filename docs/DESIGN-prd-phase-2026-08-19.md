## 一、StagePass 在这个阶段只提供三样

**题面**、**阶段判断**、**产物**。用户原话，一个字不多。

其余全部发生在他自己的 Codex / Claude Code 会话里。

## 二、回路

```
①  人和模型自由聊                        StagePass 不参与，不知道，也不该知道

②  模型觉得差不多 → stagepass_ask        面板弹到人面前，他选，答案回到模型
       └ **一次一条**，问到模型觉得够了
       └ 每一问一答进账本，挂在 (Change, 阶段) 上

③  模型 → stagepass_brief 拿七节题面 → 写 docs/PRD-<CHG>.md

④  人在浏览器上逐节读、逐节留意见         **正文不动**，意见挂在节的 key 上

⑤  模型 → brief（这次带回正文 + 没被回应的意见）→ 改 → 重写文件
       ④⑤ 循环，直到人不想再提

⑥  人放蓝方：另开一条会话，蓝方自己拉蓝方题面（只给正文 + rubric）

⑦  代码判形式全绿 →「进 Spec」亮 → 人点
```

**②是这次新增的**，也是上一版设计整个漏掉的那一步。

## 三、四个决定，和它们的理由

### 3.1 「备一轮」整套退休

`ask` 原来要求先有一条 `status='waiting'` 的 `HandedRound`，没有就回 `no_open_round`。
**而②发生在聊天阶段，那时根本还没有轮。** 人一上手就撞墙，撞的是这堵多余的墙。

判据降一级：**从「哪一轮」降成「哪个 Change、哪个阶段」** —— 阶段本来就在 Change 的
状态里。轮次由「这个阶段交过几版 PRD」推出来，聊天阶段是第 0 轮。

跟着退休的还有：面板上的「取题面 / 我自己跑 / 结算」三个按钮、`HandedRound` 作为
提问的前置。（`HandoffStore` 本身先留着，Spec 之后的阶段还没重做。）

### 3.2 人只提意见，不动正文

用户定的。正文始终由模型写，人只判。

于是审计链是**「意见 → 模型怎么改的」**，而不是一份看不出所以然的 diff ——
这正是「账本记的是分叉，不是进展」。

意见挂在 `<!-- section: key -->` 的 key 上，和 rubric 的 criterion 挂法是同一套
（`phase-template.ts` 已经这么干了），所以浏览器逐节渲染、逐节留言是天然的。

### 3.3 没有「交稿」工具 —— 模型直接写文件

StagePass 看到文件变了就存一版进账本。

这样模型和 StagePass 之间的接口**就是一个目录**：零 API、零版本、零协议，厂商怎么
迭代都打不到。而版本历史不依赖人去 commit（人可能整天不 commit，那审计链就断了）。

代价：一轮的边界模糊了，模型改到一半也会存一版。可接受 —— 多存几版比丢版本好，
而且「他改了三次才定」本身就是分叉信息。

### 3.4 对抗保留，但挪到人提完意见之后

用户定的。蓝方挑的是**「你俩一起没想到的」**，不是「你想错了」——
PRD 是人的意图，没有客观对错。

所以蓝方**不挡门**（用户定的两道闸：代码判形式 → 人点头）。它的产出摆在浏览器上
给人看。

## 四、阶段判断（两道）

| 道 | 判什么 | 谁判 |
|---|---|---|
| 一 | 七节都非空 · **每条意见都有下文**（改了，或明说不改并给理由） | **代码** |
| 二 | 这份 PRD 是不是我要的 | **人**，一次点击 |

蓝方的发现只摆着，不进闸门。

**这是整个阶段唯一的一次点击。** 其余全在会话里。

---

## 五、模型这一侧的工具面（全是 pull）

```
stagepass_ask(question, options[], why?)      问人一句，弹表单，等他选
stagepass_brief()                             拿当前该干什么：阶段 + 七节题面 + rubric
                                              + 上一版正文 + 没被回应的意见
```

`ask` 的 `ordinal` 在 PRD 阶段一律 null（没有判据单）——**这一格该从必填降成可选**，
它是给后面有判据单的阶段留的。

**模型能生成的仍然只有两种东西：枚举里的选择，和散文。** 没有 id、没有路径。

---

## 六、人这一侧（浏览器）

只有三件事，全部常驻，不藏在按钮后面：

1. **逐节读 PRD**（七节，模型写的）
2. **逐节留意见** + 看每条意见的下文（模型改了没有、怎么改的）
3. **「进 Spec」** —— 形式全绿才亮

加上一块只读的：**蓝方挑出了什么**（不挡门）。

阶段环不动（用户明说）。

---

## 七、还没解决的一件事

**⑥ 那条蓝方会话要人手动开。** StagePass 开不了会话 —— 开了那条线程就归它，人在
Codex App 里打不开（2026-08-19 已定案）。

摩擦已经压到一句话：人开新会话，说「你是这一轮蓝方」，蓝方自己调 `brief` 拿题面，
不用粘任何东西。

**如果连这一句都嫌多，PRD 阶段的对抗撑不住** —— 那就退回「PRD 不做对抗」。
用户已经选了保留，所以先按保留做，但这一条留着当观察点：**如果三次里有两次他没开
蓝方，就说明这层在 PRD 撑不住。**
