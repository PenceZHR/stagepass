# iteration 流水

> **只追加。**MVP 阶段的工作单位：一段反馈 = 一条 iteration。
> 主要发生在 M1（M0 是第一条，M2 不是 iteration，它把所有 iteration 横过来）。
>
> **这里存的是你的原话，不是文档。**原样粘贴，不要总结、不要润色、不要组织语言。
> 理由：原话不可重导，对原话的总结可重导。半年后你要的是当时的措辞 ——
> 里面有犹豫、有你没意识到的假设、有你后来改了口的说法，总结会把这些全抹掉。
> 写作成本因此是零：复制粘贴。
>
> **大部分 iteration 只有原话和一行「做了什么」，没有别的 —— 这是对的，不是漏。**
> 大部分 iteration 产生工作但不产生学习。真有学习时才去 `LOG.md` 追一条，
> 并在那条上带回 `it-NNNN`。
>
## 为什么必须原子化

**价值不在切分，在地址。**`LOG` 条目挂 `it-NNNN`、commit 挂 `it-NNNN`、
边界改动挂 `it-NNNN` —— 没有这个地址，所有记录都是浮的，能读但关联不起来。
（和 rubricId 是同一个技法：把「有没有关系」从语义判断变成引用完整性。）

## 在哪里切

> **在信息进来的地方切，不在活干完的地方切。**

边界的意义是「这里有新信息到达」。在没有信息进来的地方切开只增加 id 数量，
不增加可追溯性 —— 那是伪切分。

由此，序列天然是这个形状：

- `it-0001` —— **唯一没有前置反馈的一条**，是初始押注。
  简要 PRD + spec + plan + build 全打包进去都行 ——
  因为它们会被 `it-0002` 的反馈**一次性同时检验**。
  拆成三条反而更糟：PRD 错了要到第四条才知道。
- `it-0002` 起 —— 每一条都以一段反馈开头。

**边界拿不准就拆细。**细的无害（多几个 id），粗的有害（几件事的学习混在一起，
半年后拆不开）。

## 四条硬规矩

1. **边界是可观察事件，不是判断** —— 你说话了就是边界，不用想「这算不算新的」
2. **id 单调、不重用、不重排** —— 永远不要为了整洁重新编号，那会让所有旧引用
   一次性失效，而旧引用是这套东西的全部价值
3. **粒度可以严重不均匀** —— 三小时和三分钟的都是一条。它是地址，不是度量单位。
   试图让它们大小一致，等于把判断放回来
4. **已发出的 id 冻结** —— 被 LOG 或 commit 引用过就不许合并、不许拆分。
   发现切错了在下一条里说明，不回头改

格式：

```
## it-NNNN | YYYY-MM-DD
> 原话，原样粘贴

做了：一行
```
