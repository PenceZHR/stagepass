## 四、这次验出来的、会再咬人的

### 4.1 `-a never` 会掐死 elicitation（可复现）

`-a never` 不只管 shell 审批，它让 Codex **自动 decline 掉 MCP 的
`elicitation/create`** —— 而那是 StagePass 唯一的问人通道。失败是静默的：回来的
是一个格式完全合法的 `{"action":"decline"}`，和"人按了 Esc"一模一样。

`pnpm probe:elicit never` / `on-request` 各跑两次，稳定：

| `-a` | 选择器 | 客户端回什么 |
|---|---|---|
| `never` | **不画** | `{"action":"decline"}`，秒回 |
| `on-request` | **画** | `{"action":"accept","content":{...}}` |

**类型上已经不可表达** —— `CodexInvocation.approval` 只接受
`"untrusted" | "on-request"`。写注释叮嘱下一个人不如让它编译不过。

### 4.2 但 `on-request` 的代价是：turn 会停在审批上等人

从面板派发一次真 PRD turn，模型要写文件，Codex 弹出 *Would you like to make the
following edits?* —— **整个 turn 停在那儿**：rollout 二十分钟不长一个字节，进程
活着，没有错误、没有任何迹象。按一下 Enter，**10 秒后 `task_complete` 出现**。

**两档各有一种停，没有第三档，「无人值守跑 turn」在当前权限模型下没有解。**
这也是面板真正的分量：Terminal.app 那条路上提示藏在可能被最小化的窗口里，
StagePass 只会静默等满 30 分钟报"超时"，真正的原因根本看不见。

### 4.3 `/opt/homebrew/bin/codex` 是个几 KB 的 Node 包装脚本，不是真二进制

对它跑 `strings` 会得到一片 0 命中，看起来像"这个配置键不存在"，**其实什么都
没搜到**。真二进制在 `@openai/codex-darwin-arm64/vendor/.../bin/codex`，259MB。
老交接 §五.9 那条"八个候选名全 0 命中"就是这么来的（结论碰巧仍成立，但当时没有
证据）。凡引用 `strings` 结论处，以真二进制为准。

### 4.4 TUI 的文字不能用普通正则匹配

它用**光标移动而不是空格**排版，`Allow the X MCP server` 在字节流里是
`AllowtheXMCPserver`；CSI 序列还有中间字节（`ESC [ 0 SP q`），
`[0-9;?]*[a-zA-Z]` 这种模式漏掉它。**先剥转义、再去掉全部空白，然后匹配。**
这个坑让我两轮把"探针没按到按钮"误读成"Codex 没画选择器"。

### 4.5 这个环境的 `grep` 是 ugrep，`\|` 不当或运算符用

我用它查 `/api/run` 得到"未命中"，差点以为改动丢了 —— 实际全在。**用 `-E`，
或者用 python 逐个数。** 这条会让你对代码现状做出完全错误的判断。

### 4.6 别让模型当触发器

最早的探针要模型去调工具，**六轮里四轮它根本没调**，每轮十几分钟什么也没答出来。
改成探针自带 MCP 服务端、在工具调用里直接发 elicitation，一轮几分钟且确定。

### 4.7 面板静态资源必须 `no-store`

改着改着浏览器拿缓存，看起来和"改了没生效"一模一样。已加，但**如果你看到界面
没跟着代码变，先确认不是在看 `file://` 那个预览 tab**（编辑 `panel.html` 时
harness 会自动开一个，那里 `/api/panel` 取不到，界面是残的 —— 不是面板坏了）。

## 五、UI 还要改的

### 5.0 用户 2026-07-29 明确提的四条（优先级最高）

原话意思，不要打折：

1. **主页保持精简 —— 那个环的页面只要一个环，要有设计感。**
2. **每个阶段的 pass / fail 用不同颜色表示** —— pass 变绿，fail 变黄。
3. **点击环上的每一个圈（每个 stage）时，弹窗显示这个阶段现在的问题。**
   （后来又加了悬停常驻面板，两个都要 —— 见 §5.0.2）
4. **不要让 UI 被污染掉。**

第 4 条是前三条的总纲：**新东西默认不进主屏。** 现在主屏底部那条决策区
（风险 chip + gate 结论 + 两个按钮）就是第 4 条要清掉的东西 —— 它是我为了
把闸门信息塞进来加的，正是"污染"。**信息挪进弹窗，主屏只留环。**

#### 5.0.1 「一个环」是什么意思（用户当场纠正过我一次，别再搞反）

我第一次理解成"把小环也精简掉"，**错了**。用户原话：

> 我只要一个 UI 界面的一个**大环**，不是说**小环**里面要去掉。
> 现在的 UI 不要填，我只觉得太拥挤了，我是想精简一点，不是说要变那个小环。

对应到代码：

| 说的是 | 代码里是 | 怎么办 |
|---|---|---|
| **大环** | `.halo` 那条实线轨道，**和 `.halo::after` 那圈内层虚线** | **只留一条。** 同心的第二圈去掉 |
| **小环** | `.stage-node button` —— 每个阶段那个细描边的圆 | **不动。** 它们是他要的，别削 |

**方向是减，不是加。** "现在的 UI 不要填" —— 任何"顺手补个提示/加个摘要"的
改动都违反这条。觉得主屏缺信息，答案是弹窗，不是往环那屏塞。

#### 5.0.2 阶段状态常驻面板（用户 2026-07-29 后来提的，可能替代弹窗）

原话：

> 原始的比例不是 2:2:6 吗？你说那个圆环其实占 6 的位置。我希望圆环那整个页面，
> **左边 40% 的位置可以用来常驻显示每个 stage 的状态**。比如说我的鼠标挪到了
> Spec 的位置，然后我左边就刷新成 Spec 的状态。然后我要是 PRD 的位置，那就显示
> PRD 的状态，**随着我的鼠标变动**。如果我的鼠标没有点任何的小圈儿 stage，
> **那就恢复到原始的状态**。

行为很清楚：**悬停驱动**。鼠标移到某个节点 → 左侧面板刷成那个阶段的状态；
鼠标离开所有节点 → 回到默认。

**两处歧义已经问过用户，都定了（2026-07-29）：**

1. **「左边 40%」是第三列内部的 40%。** 也就是那个 `6` 的区域再分
   **40 / 60** —— 左 40% 状态面板，右 60% 放环。
   **Projects / Changes 两列保持不动**，整页仍是 `2 : 2 : 6`。
   - **⚠️ 连带后果：环只剩第三列的 60%，会比现在更小。** 而他先前明确抱怨过
     环太小、比例不协调。**所以这一条不能只改宽度 —— 必须同时把环放大**
     （现在是 `.orbit-wrap { max-width: 78% }`，且高度先定；在 60% 的容器里
     要重新配比，让环看起来仍然是主角）。改完务必截图自查。
2. **是补充，不是替代。两个都要。**
   - **悬停** → 左侧常驻面板刷成那个阶段的状态（概要）
   - **点击** → 弹窗显示那个阶段完整的问题列表（明细）
   - 信息分两层。**注意弹窗会盖住环，所以它必须能干脆地关掉**，别变成第三层
     常驻内容。

**这一条不违反"不要污染 UI"** —— 它是把信息从主屏挪到一个常驻的、有固定位置
的地方，而不是往环那屏加东西。**同时，底部那条决策区要撤掉**（§5.0 第 4 条），
它的内容归到左侧面板与弹窗里。

#### 落地时要先定的四件事（我没有替他定）

- **~~一个环是几层~~ —— 这条用户已经说清楚了，见下面 §5.0.1，不要再当成待定。**
- **pass / fail 从哪里读。** 数据模型里**没有 per-phase 的 pass/fail 字段**。
  能用的原料：`change_events` 账本里的 `approve` / `reject`、`gaps` 里该阶段
  还有没有 open、`change_evidence` 有没有该阶段的行。**这个映射必须先定死并
  写进 PRD**，否则颜色会变成一个没人能说清含义的装饰。
- **绿/黄怎么落到这套色板里。** 设计稿 §3 明确禁止高饱和警示色，并写着
  **"不依赖颜色作为唯一状态表达"**。所以要用低饱和的灰绿与暖沙金/陶土，
  并且**颜色之外还要有第二个信号**（对勾、描边粗细、文案）。这不是跟用户
  拧着来 —— 是同一份设计稿的硬约束，实现时一起满足。
- **「请 Codex 问我」搬到哪。** 主屏要清空，这个主动作最自然的去处是弹窗里
  那个阶段的底部。**但它仍然只能是"把裁决交给 Codex 问"，不能变成弹窗里的
  approve/reject 按钮**（§5.3 第 2 条）。

#### 弹窗里放什么（有现成数据）

`GapStore.all(changeId, phase)` 已经给出该阶段全部 gap（含 `status`：
open / closed / waived、`openedRound`、`resolution`）。
`CommandStore.gateFor(changeId)` 给闸门结论。
**这两样都是读接口，不写 —— 弹窗只显示，不改状态。**

### 5.2 我自己观察到的粗糙处

- **阶段视图里看不到闸门**：进了终端就只有终端。**注意这条和 §5.0 第 4 条有张力** —— 别为了补它又往主屏加东西，答案应该在弹窗里。

### 5.3 改 UI 之前必须知道的三条硬约束

1. **`src/web/` 里不许把 pty 输出变成 string。** 常驻测试第五条会红。禁的 token：
   `TextDecoder` / `.toString(` / `JSON.parse` / `String.fromCharCode`。
   这不是洁癖 —— 它是终端面板被接受的前提条件（PRD §9.3）。
2. **网页上不许有 approve / reject 按钮。** 决策区只显示闸门说了什么，主动作是
   「请 Codex 问我」，裁决发生在 Codex 自己的选择器里。
3. **节点用三角函数放在同一个圆心和半径上**，不许各自用近似百分比定位（设计稿
   明写）。悬停放大只作用在自己身上，不许推动圆环。

**版式上已经踩过的两个坑**（别再踩）：`.col-head` 是 flex 且默认不换行，
`flex: 0 0 100%` 会把标题挤成零宽只剩一个字母；圆环若只按宽度定尺寸，标题一
占位底部节点就掉到列外 —— 要高度先定、宽度由 `aspect-ratio` 推出来。

## 七、我这次犯的错，写下来免得重犯

1. **说好让用户决定的事，自己顺手做了。** 我说 artifact「留不留是你的决定」，
   然后用 `git add docs/` 把它一起提交了。**范围语句一旦说出口，就要在动手时

2. **拿 `grep` 的空结果当"代码里没有"。** 见 §4.5。差点据此得出"改动丢了"的

3. **抄错了原型。** 阶段环的节点照着 brainstorm 里那份圆角方卡的探索稿做，而

   而只有 approve/reject/retry 会被拿去问 —— 会问出一个 `no_decision_available`。
