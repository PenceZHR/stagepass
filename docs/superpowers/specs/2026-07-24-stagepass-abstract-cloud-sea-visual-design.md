# Stagepass 抽象云海视觉重设计

日期：2026-07-24
状态：已确认视觉方向，等待书面规格复核

## 1. 目标

Stagepass 继续作为独立、完整的产品表面，但职责收敛为：

- 展示当前 Change 的流程位置与门禁状态；
- 展示用户作决定所必需的风险与证据摘要；
- 承载批准、拒绝、继续对抗和风险接受等人类决定；
- 提供进入对应 Codex task 查看完整过程的入口。

完整推演、长文本过程、Agent 输出和多数执行细节留在 Codex。Stagepass 不复制 Codex 内容，也不退化为 Codex 内嵌卡片。

## 2. 已确认的视觉方向

方向名称：**Abstract Cloud & Sea Motion**

核心印象：

- 低饱和晚霞；
- 抽象云层位于顶部；
- 抽象海面位于底部；
- 中部保持低细节和充足留白，用于门控信息；
- 画面安静、克制、有流动感，但不拟真、不霓虹、不喧闹；
- 保留 Stagepass 原有的工程流程、红蓝对抗、人工裁决与档案感。

云和海使用一张真实生成的抽象栅格资产，不用 CSS 图形伪造。视觉处理为半透明水彩色层、雾状轮廓、纸张颗粒与水平波纹。不得出现可辨认的写实云朵、细密水面反射、太阳圆盘、船、鸟或陆地。

## 3. 色彩

主色保持低饱和：

| 用途 | 色彩 |
|---|---|
| 暮色背景 | 灰紫、暮蓝、烟粉 |
| 云层高光 | 暖沙金、柔和杏色 |
| 海面 | 石板蓝、灰紫 |
| 风险 | 陶土红，不使用高饱和警示红 |
| 已验证状态 | 暖沙金或灰绿 |
| 主要文字 | 暖白 |
| 次要文字 | 透明度 48%–68% 的暖白 |
| 面板表面 | 暮色背景上的半透明深灰紫 |

禁止：

- 高饱和橙、亮粉、荧光紫和霓虹蓝；
- 大面积纯色警告背景；
- 与抽象云海无关的彩虹渐变；
- 依赖颜色作为唯一状态表达。

## 4. 页面构图

### 4.1 顶栏

顶栏保持轻量：

- 左侧为 `stagepass` 字标；
- 中间显示 Project / Change；
- 右侧显示本地状态；
- 使用轻微背景模糊和细分隔线，不做厚重导航栏。

### 4.2 流程轨道

保留现有 Pipeline 抽屉和阶段选择行为，不因本次视觉重设计改变信息架构。流程导航展开时，使用紧凑轨道显示当前产品实际阶段：

`PRD → Spec → Tech Spec → Plan → Test Plan → Build → Review → Fix → QA → Merge → Retro`

规则：

- 已完成阶段使用暖沙金或灰绿；
- 当前阶段使用暖色呼吸点；
- 后续阶段降低对比度；
- 轨道是按需查看的定位信息，不恢复为长期占据正文宽度的常驻侧栏；
- Refine 与 Provider 选择不得重新出现。

### 4.3 主门控区域

视觉层级从高到低：

1. 当前 Gate 与是否等待人工决定；
2. 一句清晰的门控结论；
3. P0 / P1 / P2 中真正影响放行的风险数字；
4. 我方主张与反方异议的必要摘要；
5. 人类决定动作；
6. 查看必要证据与打开 Codex task 的入口。

主界面不承载完整对抗记录、长篇 Agent 输出或执行日志。

### 4.4 决策区

决策区固定在主内容的视觉收尾位置，使用一层半透明深色表面。

- 主动作只保留一个；
- 次动作最多两个；
- 风险接受必须明确说明会保留审计记录；
- 按钮不得漂浮在页面之外或使用高饱和渐变；
- 关键决定不能只依靠图标表达。

## 5. 背景资产

目标尺寸：`1536 × 1024`，横向。

构图：

- 上方约 30% 为抽象云层色带；
- 中部为低细节、低对比的留白区；
- 地平线位于画面中线下方；
- 下方约 28% 为抽象海面水平纹理。

建议项目路径：

`public/assets/stagepass/abstract-cloud-sea.png`

资产进入实现时必须复制到项目目录，不得依赖 Codex 全局生成目录或临时预览目录。

## 6. 动效

所有动效使用缓慢、连续、可预测的节奏。

| 动效 | 建议周期 | 行为 |
|---|---:|---|
| 基础背景呼吸 | 18s | 缩放约 1.03–1.08，水平位移不超过 1% |
| 顶部云层漂移 | 24s | 独立图层缓慢横移约 5% |
| 底部海面视差 | 12s | 水平位移约 1.6%，垂直位移约 0.6% |
| 地平线呼吸 | 5s | 透明度与柔光缓慢变化 |
| 当前阶段呼吸 | 2.8s | 轻微缩放与柔光变化 |
| 决策区浮动 | 6s | 垂直位移不超过 3px |
| 标题渐变流动 | 8s | 低对比渐变缓慢横移 |

约束：

- 禁止快速闪烁、无限旋转、强烈弹跳和粒子喷射；
- 动效不能改变内容位置到影响点击；
- 页面必须支持 `prefers-reduced-motion: reduce`；
- 减少动效时保留静态云海、清晰状态和全部功能；
- 动效不能成为理解门禁状态的必要条件。

## 7. 字体与表面

- 品牌字标、主标题和重要结论使用克制的衬线体；
- 状态、按钮和辅助信息使用清晰的无衬线体；
- 技术状态码只在必要位置使用等宽体；
- 主标题保持短句和大留白；
- 面板采用半透明深灰紫，不使用多层玻璃卡嵌套；
- 边框使用低透明度细线，阴影只用于区分主要门控表面。

## 8. 响应式

桌面端：

- Pipeline 抽屉收起时把宽度留给正文，展开时显示完整阶段轨道；
- 主区并排展示必要摘要与风险数字；
- 决策动作保持在同一视觉收尾区域。

窄屏：

- Pipeline 抽屉保持按需打开，正文只显示紧凑的当前阶段摘要；
- 风险大数字可折叠到门控标题下方；
- 我方与反方摘要改为单列；
- 决策按钮可换行，但主动作始终排在第一位；
- 抽象云海仍保持“上云、下海、中留白”的构图。

## 9. 可访问性

- 暖白文字与背景的实际对比度必须满足 WCAG AA；
- 风险、完成、当前阶段同时使用文字或形状，不只使用颜色；
- 所有动作支持键盘访问和清晰焦点态；
- 背景资产必须使用装饰性空 `alt`；
- 动效图层不得捕获点击或键盘焦点；
- 风险接受需要可读的确认说明；
- 缩放至 200% 时不遮挡主要动作。

## 10. 明确不做

- 不把 Stagepass 变成 Codex task 内嵌卡片；
- 不在 Stagepass 重复完整 Codex 对话和推演内容；
- 不恢复 Provider 选择；
- 不恢复 Refine 阶段；
- 不使用写实海景、照片式云层或风景壁纸感；
- 不使用鲜艳霓虹晚霞；
- 不把所有信息放进独立卡片；
- 不为了展示动效而增加无业务意义的元素。

## 11. 验收标准

视觉实现完成后必须满足：

1. 第一眼可以辨认顶部抽象云层与底部抽象海面，但不会误认为照片；
2. 颜色明显属于低饱和晚霞，而不是霓虹渐变；
3. 页面静止截图仍具有清晰的 Stagepass 品牌识别；
4. 动画运行时能感知云、海和门控状态的不同节奏；
5. 减少动效模式下仍完整可用；
6. 用户在五秒内能回答当前阶段、阻塞原因和主动作；
7. 完整过程内容明确留在 Codex，Stagepass 只显示门控与必要信息；
8. 不出现 Refine、Provider 选择或写实背景；
9. 桌面和窄屏均不存在文字裁切、按钮溢出或背景干扰阅读；
10. 所有关键操作、状态与风险提示通过可访问性检查。

## 12. 验证方式

- 使用桌面与窄屏两个视口检查布局；
- 对比静态、默认动效和减少动效三种状态；
- 检查云层、海面、地平线、阶段呼吸与决策浮动的周期和位移；
- 以真实 Gate 数据验证短标题、长标题、零风险和多风险状态；
- 使用键盘完成查看证据、继续对抗和风险接受；
- 对关键文字与按钮执行对比度检查；
- 在 200% 缩放下复查主动作和风险说明。
