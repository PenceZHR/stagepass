# 回跳 = 轨道转移：小火箭动画 + 删中心圆盘

2026-08-09 · 用户拍板方案 A（轨道转移隐喻），附带删掉环中心圆盘。

## 问题

环上「回跳」现在有两样红色视觉，用户判定丑：

1. **历史红线**（`.chord` / `.chord.hot`）：走过的回头路，穿过中心的红实线弦，永久留着。
2. **回跳选项动画**（`.live.back` + `.arrow.back`）：现在能回跳的边，淡红发丝上循环飞三个红 V 字。

另：环中心的圆盘（`.center`）显示当前阶段名 / Gate 状态 / approved 计数——左侧面板和节点本身都有这些，纯重复；且它 `z-index: 4` 盖住环内部，正好挡着弦。

## 设计哲学（用户原话的展开）

回跳讲成一次航天动作：**小火箭从起点 stage 的环形轨道（RIM 圈）起飞，飞到目的 stage 的环形轨道入轨**。脱离轨道 → 转移 → 入轨。

## 设计

### 1. 火箭本体

- 描边小火箭，与现有 V 字同笔触：stroke ≈ 0.5、圆头圆角、无填充。
- 形状：尖头 + 梭形箭身 + 两片小尾翼，全长约 2.4 viewBox 单位（比 V 字略大一号，仍是发丝量级）。
- 头朝 +x 画，靠 `animateMotion rotate="auto"` 扭向飞行方向。
- 尾部两根短线做喷焰，SMIL 轻微闪动——只有喷焰闪，箭身不闪。

### 2. 飞行路径与节奏

一条复合路径三段连成一笔（一个 `<path id>`，火箭骑 `mpath`）：

| 段 | 几何 | 节奏 |
|---|---|---|
| ① 起飞 | 贴起点 RIM 轨道滑行约 60° | 慢（蓄力） |
| ② 转移 | 切线脱离，向环心弯的贝塞尔（保住「穿心 = 回头」旧语义） | 加速到最快 |
| ③ 入轨 | 切进目的 RIM 轨道滑行约 120° | 减速，末端淡出 |

- 缓动用 `animateMotion` 的 `keyPoints`/`keyTimes`（calcMode linear 分段逼近）。
- 淡出停一拍再从头来，整循环约 6~7 s；透明度用同 `dur` 的 `<animate>` 同步，不露「瞬移回起点」。
- RIM 圈就是自环 V 字骑的那个轨道（`RIM = 7.5`），几何常量复用，不另立数。

### 3. 历史红线 → 凝结尾迹

- 同一条弦的几何，端点缩到两个 RIM 轨道上。
- 画成极淡圆点虚线（暖沙偏余烬橙，透明度 ~0.35），像残留烟迹。
- `sendBack`（现 `.hot`）比其它回跳略暖略亮一档，语义分层保留。
- tooltip（第几轮、理由）原样不动。

### 4. 删中心圆盘

- 删 `.center` 整个 div、其 CSS（含 `centerFloat`）、panel.js 里 `drawCenter` 对
  centerKicker/Title/Line/Count 的写入与四个 `pick`。
- **进度弧保留**：`drawCenter` 里 `--progress` 那半截还有用，函数瘦身不删除。
- reduced-motion 规则列表里去掉 `.center`。

### 5. 不动的东西

- 向前的边、自环：V 字照旧。火箭是回跳专属。
- 回跳选项保留一根极淡完整飞行路径发丝，只为 hover tooltip（`edge.why`）。
- `prefers-reduced-motion`：火箭静止在起飞点、朝向路径方向，喷焰不闪。
- 数据流、服务端、panel-view.ts 零改动。只动 `panel.js` 与 `panel.html`。

## 验证

- `pnpm check` 全绿。
- 真面板实看：从真终端起面板，demo 项目造一条有回跳历史 + 回跳选项的 Change，
  浏览器里核对起飞/入轨节奏、烟迹、tooltip、reduced-motion。

## 追加（2026-08-09 第二次拍板）：幽灵火箭

上线后用户第一眼就问「火箭怎么没有」——回跳**选项**开着的时刻很短，只给活边配
火箭的话它 99% 的时间没有出场机会。拍板：**最近一次回跳的烟迹上有一枚淡一级的
幽灵火箭定期重飞**（同样起飞→转移→入轨），其余老账保持静态烟迹，环不变机场。
路径不画（rail），烟迹已说明路线；若活边恰好同路，两枚火箭同相叠住，视觉上就是
一枚。

## 追加（2026-08-09 第三次拍板）：螺旋轨道

用户看过完整任务版（发射斜升/垂直降落 + 两端各绕两圈）后否掉了起降那两笔：
「不要登陆和发射的垂直动画，就做到直接绕圈，但是绕圈的时候轨道要越来越远，
降落的轨道越来越近直到着陆」，并追加「轨道可以大一点夸张一点」。

定稿设计语言：**螺旋**。从 stage 圆边上（NODE_R=4.86）起旋，两圈外扩到
ORBIT_MAX=12（故意大过 RIM 的 7.5），切线转移，到目的端从 12 两圈内收到
4.86 贴圆着陆，停一瞬熄灭。螺旋用四分之一圈一段的三次贝塞尔逼近，接缝 G1
连续；缓动 calcMode=spline（起旋慢→转移最快→着陆前收）。

已知代价：3 点钟 / 9 点钟方向的节点贴着窗口边，夸张外圈的靠边半侧会短暂
飞出屏幕再回来。要完全不出屏只能把主环缩小（MAP_RADIUS），不值得。

### 修正：外圈按余量收，别飞出屏幕

上一段记的「已知代价：靠边半侧会短暂飞出屏幕」实测下来不是可接受的代价 ——
火箭在那一段**整个消失**（12 的外圈让路径跑到 x=106.6，而窗口只铺得到
x≈103.2；`overflow` 一路 visible，裁掉它的是窗口边缘不是 CSS）。

改成 `outerOrbit(node)`：外圈 = clamp(到 viewBox 最近边的余量 + 3, RIM, 12)。
四个对角节点照样飞满 12，四个正轴节点（三点/九点/十二点/六点）收到 7.5 ——
正好等于现有自环 V 字的轨道半径，不引入新的溢出。**看得见比一样大要紧。**

实测（1280 宽窗口，最坏情况 Arch↔Test）：路径右端 1278px < 窗口 1280px，
左端 822px > 中间栏文字右界 793px，两头都不越界。

## 追加（2026-08-09 第四次拍板）：匀速、不画轨道、环心放太阳

用户看完螺旋版提了三条，外加一条新需求：

1. **「小火箭不要急停，线性的速度变化」** —— 前一版用 keyPoints + keySplines
   分段调速，末尾还抱着终点停 16% 时长。那个停顿就是「急停」，而分段无论怎么
   配缓动，交接处都是看得出的换挡。改成**什么都不设**：`animateMotion` 的默认
   calcMode 是 paced，按弧长匀速走完整条路；收尾靠 opacity（最后 10% 边飞边淡），
   不是停。
2. **「轨道不要画出来」** —— 历史那条弦整条不再渲染（连透明的 hover 命中区也
   撤了：看不见的悬停目标没人找得到，而它横穿环心会吃掉太阳的点击）；活边的
   飞行路径降为 `rail`（只当 mpath 的跑道，不画不吃鼠标）。代价：回跳边的
   `edge.why` 在环上没有落点了 —— 左侧面板的「闸门」那行仍然在说能不能走。
3. **「中间太空了，想插入一个太阳」**，且要**卡片可爱剪纸风格**、要**日冕小动画**、
   **点击太阳出现阶段状态**（就是本文档最初删掉的那块信息）。

太阳的做法：内联 SVG，三层平涂色块（深色底纸错开 3.2 露出厚度 / 脸 / 高光），
没有一处渐变 —— 渐变是照片的语言，剪纸的语言是平色和看得见的边。日冕是 8 长 +
8 短两组光芒，整组 44s 慢转，两组亮度**反相**呼吸（同相会读成整体忽明忽暗，
像坏了的灯）。点太阳翻出状态卡（Gate 状态 / 当前阶段 / 第几个 / approved 计数），
再点收回；卡摆在太阳下方不盖住它，一个开关管两头。

### 两个实测坑

- **SVG 的 `transform-origin: center` 不能用**。viewBox 是 `-50 -50 100 100`，
  太阳中心是用户坐标原点，`center` 实测（Chrome）解析成 `50px 50px`，日冕会绕
  一个偏出去的点公转 —— 症状是**太阳裂成两半**，脸在环心、光芒飘到右边。写 `0 0`。
- **状态卡会被节点压住**。`.stage-node` 是 z-index 6（悬停 12），卡必须更高
  （13）；且竖排的计数把卡撑高 30px，正好撞上六点钟的节点 —— 计数改排成一行。

## 追加（2026-08-09 第五次拍板）：统一成剪纸火箭、各走各的道、去了要回来

用户三条：「整体风格统一一下」「小火箭不要追着，要在不同轨道，你现在的小火箭都
同一轨道飞行」「小火箭飞出去还要飞回来」。

**统一**：环上会动的东西**只剩火箭**一种。V 字箭头（`flyingArrow`）整套退役 ——
环心放了剪纸太阳、线条又全撤之后，细描边的空心 V 成了屏幕上唯一还在说旧方言的
东西。火箭改成平涂剪纸：奶油机身 + 挖空的圆窗（填背景色，像纸上剪掉一块）+
褐色后掠鳍 + 更亮更黄的火苗。**火苗和鳍必须差色**：同色会糊成一整块楔形，看不出
哪是鳍哪是火。叠放顺序即贴纸顺序：火苗 → 鳍 → 机身 → 挖窗。

**各走各的道**：自环从「两枚 V 在同一圈上前后隔半圈」改成**两枚火箭、两条不同
半径的圈、两个不同周期**（6.5s / 10s，不整除所以永远错开）。跨阶段的边每条只有
一枚火箭，不再排队。

**去了要回来**：所有航线都是**闭环**。
- 回跳：起点螺旋外扩 → 向心弯的转移弦 → 目标螺旋内收贴到圆边 → 一笔鼓向弦的
  另一侧回到出发点（`returnApex`，去程向心、回程外鼓，两条道分得开）。
- 推进：沿环的**跑道形**——外道 45.5 去、内道 37.5 回，两头各半个 U 弯（U 弯圆心
  摆在内外两道正中间，接口处两侧切向都是纯周向，拼起来不打折）。实测半径剖面
  45.5 → 37.5 → 45.5，五条路径首尾距离全是 0。

闭环还有个副产品：**淡入淡出可以整个删掉**。起点就是终点，`repeatCount=indefinite`
接得严丝合缝，不再需要 opacity 去抹单程的瞬移。

### 一个实测坑

火箭放大不能写在挂 `animateMotion` 的那个 `<g>` 上 —— animateMotion 自己往上写
transform，会把 `scale()` 顶掉，火箭悄悄回到原始尺寸。要**两层 g**：外层归动画，
内层放缩放。

## 追加（2026-08-09 第六次拍板）：回程也得是完整的轨道过程

用户原话：「我的设计理念是从一个 Stage 的地表，然后慢慢地升到轨道，到另一个
Stage 的轨道，再慢慢地降回地表。然后呢，再慢慢地升轨道，再回到原来的 Stage。
不是你这样，你去的过程是对的，但你回的过程你是直接从球里出来，那是不对的，
两个都是有轨道的过程。」

上一版的回程是从目标**地表直接拉一条弦**回起点地表 —— 一趟正经任务配一条捷径。
定稿改成**六段**：

```
① 起点地表 → 螺旋升到起点轨道
② 转移到目标轨道
③ 螺旋降到目标地表
④ 螺旋从目标地表再升回目标轨道     ← 之前缺的就是这一段
⑤ 转移回起点轨道（弦的另一侧，不是原路）
⑥ 螺旋降回起点地表 —— 正好是 ① 的出发点，闭环
```

**推进边也一样。** 既然「整体风格统一」，沿环走的推进不再是不碰地表的跑道形，
而是同一趟六段往返，只把两条转移弦换成贴着环的弧（内道回）——「沿环走 = 推进 /
穿心 = 回头」那条语义（§5.9.3④）因此保住，两种边共用一个 `rocketFlight`，
**差别只在两条转移弦怎么弯**。

### 几何上的三处要紧事

- `spiralTurns`（整圈）换成 `spiralArc`（任意扫角）。转移弦两头的切点角度是弦自己
  定的，而 ①③ 走整圈会回到原角；**④⑥ 必须在整圈之外补一个差角**，从「上一段停在
  的角」补到「这一段的弦要求的角」。补角用 `wrapAngle` 取正 —— 取负螺旋会倒着画，
  路径当场自交。
- 贝塞尔控制点长度改成 `(4/3)·tan(θ/4)·r` 按实际步长算（θ=90° 时正好是那个眼熟的
  0.5523）。拿 90° 的常数硬套非整圈的那一段会鼓出去。
- `ringArcApex` 的放大量**必须封顶**。`1/cos(Δ/2)` 是给「两端正好落在环上」算的，
  而这里两端在各自节点的轨道上。跨两格时 1.41 把控制点顶到半径 64，实测路径左边界
  跑到 x = -17，整段飞出画面。封在 30°（放大 1.155）。

### 覆盖验证

32 种组合（每个节点 × 相邻/隔格 × 前进/回跳）逐条建路径量：全部闭合（首尾距离 0），
边界最坏 -3.0 / 103.0 —— 和现有自环轨道同一个范围，换算成像素左 821px > 中间栏
793px、右 103 < 可视上限 103.2，都在画面内。

## 追加（2026-08-09 第七次拍板）：自环改卫星，火箭只管跨阶段

用户：「小火箭自己环绕自己的我要做成卫星环绕，stage 间采用火箭。」

分工从此清楚：**火箭要点火、要变轨，它属于跨阶段那趟六段旅行；「再来一轮」是原地
绕着自己转，那是卫星干的事。** 卫星因此没有尾焰，会动的是一盏信标灯（1.9s 一明
一暗）。

### 板子摊平，不是径向立着

第一版把太阳能板画成径向立起的两片，径向要占 3.4 个单位 —— 而正轴那四个节点
（三/九/十二/六点）被 outerOrbit 收到 RIM，从地表到轨道只剩 2.6。结果是：放大到
读得出形状就压到节点圆，不放大就是一个 14px 的橙点，谁也认不出是卫星。

改成**沿飞行方向左右展开**（真卫星侧视本来就是这样）：径向只占 1.8，可以放到
22px 长，塞进那条窄缝还有富余。碟子朝 local +y —— `rotate="auto"` 之下正好指向
节点圆心，对地定向不用另外算。

桁架用机身的奶油色而不是板子的橙：三样同色时整枚糊成一条。

### 地方不够就只放一颗

正轴节点的 2.6 缝里塞两条道，两颗卫星会叠在一起 —— 那还不如一颗。判据是
`outer - NODE_R >= 4.5`：四个对角节点两颗（半径 7.57 / 12，周期 6.5s / 10s 不整除，
永远错开），四个正轴节点一颗（半径 6.5，周期 8s）。
