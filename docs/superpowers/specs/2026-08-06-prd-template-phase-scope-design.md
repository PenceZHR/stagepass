# 设计：PRD 模板 + 每个阶段自己的尺度（2026-08-06）

> 起因：用户 2026-08-06「输出质量有问题，反复对抗不收敛」「PRD 阶段会涉及很多其他
> 阶段的问题，比如说架构、技术栈、测试 —— 这肯定不是他做的呀」「力度有问题，追的
> 过于细」。
>
> 这份设计承接 `BACKLOG.md` §8.2（病一：设计阶段是无限精度递归），**并且推翻了
> 那一节拟的修法**（见 §5.1）。

## 〇 · 一句话

反方今天有两条输出路：**有边界的那条不算数，无边界的那条说了算。** 这一刀把设计
阶段的输出收口到「照着固定模板逐节判 yes/no」，**让收敛第一次有机械判据**。

## 三 · 设计

### 3.1 模板：把散文变成离散的

这条理由 BACKLOG §5.6 已经推过，只是当时只用在代码上：

> **文档是连续的，改一处文字就产生新的可挑剔表面**；模块是离散的，一个 40 行的
> 模块可挑的表面小到能被穷尽。

**模板就是把文档变成离散的。格子有限 → 可挑表面有限 → 有收敛点。** 同一条判据用户
早就立过一次（「固定 Schema 而非禁止 JSON —— 判据是结构由谁决定」），这次是把它从
模型的输出格式推到**文档的结构本身**。

**存哪**：新模块 `domain/phase-template.ts`，和 `phase-play.ts` 同一层 —— 纯文本、
只 import `Phase` 类型。理由和那张表一样：每个阶段可以独自变，不许提取公因子。

**一节的形状**：

```
{ key: "problem", 标题: "要解决谁的什么问题", 要回答什么: "..." }
```

**PRD 模板拟的六节**（内容待用户改，这里是起点不是权威）：

| key | 标题 | 这一节要回答什么 |
|---|---|---|
| `problem` | 要解决谁的什么问题 | 谁在用、他今天怎么受阻、不解决会怎样。**不写要做什么功能** |
| `outcome` | 做完之后什么变了 | 可观察的结果，不是功能清单 |
| `acceptance` | 验收标准 | 每条可观察、可测量 —— **到「一个称职的实施者照着做不会做错」为止，不要求每个词唯一裁定** |
| `out-of-scope` | 这次不做什么 | 明确排除的 |
| `assumption` | 前提 | 至少一条会让整个方案不成立的前提，以及怎么判它成不成立 |
| `deferred` | 留给下游决定的 | 有意不在 PRD 定的，**写明留给哪个阶段** |

**`deferred` 这一节是承重的。** 它给了「这件事属于下游」一个**红方声明**的位置：
反方觉得某事没定，先看红方有没有在这一节声明；声明了就不是 PRD 的洞。没有这一节，
「架构没定」这种话除了开成 gap 无处可去 —— 那正是今天 18 条的来路。

**模板里还要明写「不要写什么」**：架构、技术栈、模块划分、接口、测试用例、实现步骤。

**机械判据**：产出解析回来**缺节 = 这一轮不合格**。不是叮嘱，是闸门。

**只做 PRD 一个**，跑通一轮确认形状对了再复制给别的阶段 —— 用户 2026-07-22 定的
纪律（「先只做 Spec 一个，实际用过一轮确认形状对了，再复制」）。

### 3.2 rubric 每条挂一个节

`rubric_criteria` 加一列 `section`（引用模板的 `key`）。判定仍是 **yes/no，不评分** ——
沿用既有不变量：`standard` 类 gap 结构上就没有 severity 字段（`db/schema.ts` 那条
配对 CHECK：「the question was 是否满足, which is binary」）。

`PRODUCER.PRD` 那四条按节铺开并扩充。**这是这一刀真正的工作量，而用户已经明确
选择把成本花在这儿**（第 6 条拍板）。

**悬空要能被抓住**：criterion 引用了模板里不存在的 `section` → 装默认/存 rubric 时
报错，不是静默留着。

### 3.3 反方的输出收口 —— 这一刀的核心

**设计阶段取消 blockers 这条自由列表，反方的输出就是逐条判定。**

| | 今天 | 改后 |
|---|---|---|
| 每轮上限 | 无 | **= criterion 条数** |
| 收敛判据 | **人的耐心** | **全 yes** |
| 越界 | 无人发现 | 答一个不认识的 key → 丢**那一条** |
| 颗粒度 | 无上限 | 一条 criterion 只产出**一个** yes/no |

r4 那五条词法级追问，在这个形状下被压成「验收标准可测量」这一节的**一个 no**。

**丢一条不是丢整份。** `readAssessments` 见到不认识的 key 会作废整份，那是
BACKLOG §8.2 记的第二个成因（裁判多答一条 → 本职四条一起废）。这里必须是逐条丢，
**而且丢掉的条数要在裁决表上显示** —— 不显示就是静默失效。

**Build / Review / QA 不动。** 它们的病是自审（§8.3），解法是测试归属 + 轮末 diff
闸门（§8.4），不是这一刀。这三个阶段的 blockers 承载着真正值钱的具体缺陷
（`verify.mjs` 那些绕过点），砍掉是净损失。

### 3.4 人拿到的依据（对应拍板第 7 条）

今天人按批准时手上是 139 条散着的 finding，**没有任何东西告诉他还差多少**。改后
裁决表上摆：

```
PRD 第 4 轮 · 六节 · 14 条判定
  还剩 3 个 no：acceptance ×2、assumption ×1
  这一轮有 2 条因为不属于本阶段被丢掉
```

「还剩几个 no」就是「还要不要再来一轮」的依据。**这是把收敛从感觉变成数字。**

## 四 · 三个连带问题，不解决这套白干

### 4.1 出厂 `blocking=false` —— **需要用户拍**

64 个 `no` 今天一条都不挡门。这套要成立，判定必须算数。

**拟的做法（窄口）**：**只有模板节派生的 criterion 出厂 `blocking=true`**，其余照旧
`false`。

理由：原来那条 `false` 是防「漏答视同阻断 → 新项目一上来被拦」。**在模板下漏答有了
另一个出口** —— 缺节在红方那一侧就被 §3.1 的闸门机械判掉了，轮不到反方漏答；而
反方漏判某一节，本来就该挡（那一节没人看过）。

**但这翻的是用户 2026-07-31 的拍板，必须他本人点头，不能按假设做。**

### 4.2 `installDefaults` 只补空缺

`store/rubric-store.ts:143`：已经有 rubric 的 (阶段, 角色) **一个字都不碰**，而且只在
建项目时调一次（`app/workspace.ts:75`）。

**所以扩充 `rubric-defaults.ts` 对 CHG-001 所在的项目零效果。** 这正是记忆里那个病的
复发（Review 那条旧措辞让裁判判了个假阳性的 `no`）。改完看不到任何变化。

方案没定，三个候选：重装（会覆盖人改过的，危险）／按 key 补新增的（复杂）／给出厂
标准一个版本号，`installDefaults` 升到最新版除非人改过。

### 4.3 `PHASE_PLAY.blue.task` 要跟着改

不改就是要求和判据对不上 —— `phase-play.ts:143` 那段注释记着 Build 已经栽过一次
（「rubric 加了四条编码规范，而『遗漏、冲突、不可验证』里没有一个词指向它们」）。

## 五 · 被这份设计推翻的

### 5.1 BACKLOG §8.2 拟的修法作废

原修法：`renderSettled` 的 waived 段加一句「这些是判得太细的例子，颗粒度不要超过
它们」。

**它治的是症状。** 校准信号要等有人 waive 过才有，而 PRD 第一轮就开了五条；而且它
仍然把「多细算细」留给模型判断。模板 + 一节一判把它变成结构问题：**一节只能有一个
yes/no，细到什么程度都只是那一个 no 的理由。**

### 5.2 「取消 blockers 会丢掉真发现」不是反对理由

会丢，而且用户明确接受：「就算漏了也不能留」。丢掉的那类问题**在正确的阶段会重新
出现** —— 真库里 PRD 追的「自动检查的检查项/阈值」，TestPlan 阶段确实自己开了
`TESTPLAN-PREFLIGHT-1`、`TESTPLAN-GATE-TESTS-1`。

## 六 · 不做

- 模板不铺开到十二个阶段（先 PRD 一个，跑通再复制）
- Build 的自审（§8.3 / §8.4）不在这一刀里
- 越界的问题**不转交下游**（用户已拍：漏了也不能留）
- 不动 `standard` 无 severity 那条不变量
- 不碰 `change-state.ts` 那两条硬校验（和 §8.11 同一条纪律：只补能力）

## 七 · 风险

| 风险 | 说明 |
|---|---|
| **模板节写坏了，病换个地方** | 六节的措辞就是新的天花板。缓解：它在面板上人改得动，权威在人手里 |
| **「一节一个 no」丢掉位置信息** | 一个 no 底下可能有三处具体问题。`found_where` / `found_why` 仍在，但一条 gap 只能带一组 |
| **模板会被红方糊弄** | 每节都填了但填得空。这一层只有 rubric 判得了，是判定质量问题不是结构问题 |
| **PRD 六节太少或太多** | 未验证。第一轮真跑完才知道 |

## 八 · 完成判据

1. PRD 跑一轮，红方产出**按六节**，缺节被机械判掉
2. 反方那一轮的输出**只有逐条判定**，没有自由 blockers
3. 裁决表上人看得到「还剩几个 no、卡在哪一节、丢了几条越界的」
4. **连续两轮全 yes = 收敛**，而不是靠 waive 收场

> 第 4 条是这份设计成不成立的唯一判据。今天 21 轮零空手；改后如果 PRD 仍然轮轮有
> 新的 no，说明模板没有真的封住表面，**这份设计要整体重估**。
