# 三层合成一页 · 设计记录

2026-08-17。分支 `build-the-base-2026-08-05`。

## 起因

用户原话：

> 「现在每个 stage 点开圆圈有一个界面，进去又有了一个界面，是不对的，交互太乱了，
> 统一成一个页面。」

之后补的第二句：

> 「星图可以内部再点击一个按钮跳转出来切换，其余语义要明确。」

原来穿三层：环 → `<dialog id="sheet">` 弹层 → `#stage-view` 产物驾驶舱。

## 用户拍板的三件事

1. **环是家，阶段是一整屏**。点圆圈直接进阶段页，层数从 3 降到 2。
2. **「该我干什么」和「做出了什么」两块都常驻**，落地那一眼不用展开、不用切页签。
3. **只有副屏允许藏在一次点击后面**：关系图（星图）和判定标准。其余一律常驻。

## 七块，七个问题

每一块只回答一个问题，块和它回答的问题要对得上。

| 区 | 只回答这一个问题 | 装什么 | 归谁 |
|---|---|---|---|
| 顶带 | 我在哪 | 阶段名 · 判定章 · 状态 · 线程 · 出口（← 阶段环 / 终端） | 两边各写一格 |
| 动作带 | 该我干什么 | 状态句 · 轮次进度三段 · 下一步 · 上次被拒 · 答题表单 · 闸门按钮 | `panel.js` |
| 问题栏 | 闸门在看什么 | 这个阶段产出了什么（正文一起）· 什么挡着它 | `panel.js` |
| 轮次条 | 我在看哪一轮 | 结算过的轮次；只管它底下那一片 | `stage-artifact-view.js` |
| 文件栏 | 这一轮碰了哪些文件 | 搜索 · 变更图例 · 文件树 | `stage-artifact-view.js` |
| 正文栏 | 这个文件是什么 | 正文 · 差异 · 来源 · 依赖 · 关联问题 | `stage-artifact-view.js` |
| 副屏 | 这些文件之间什么关系 / 什么算过关 | 星图；标准编辑器 | 各一半 |

左栏问的是「闸门在看什么」而不是「什么挡着闸门」，因为**产出和问题必须同栏**：
只看得见「有人挑了三条毛病」而看不见「他挑的是什么东西」，那个列表是悬着的
（用户 2026-07-30）。Build 的产出是一个 commit，而 `/api/stage-artifacts` 明确
拒收 commit（`stage-artifact-api.ts` 里 `commit-not-accepted`）—— 右边那两栏读不到
它，所以这一份不是右边的重复。

**轮次条只压在产物那一片头上，不横贯全屏**：`gaps` 不按轮次过滤（只按 `openedRound`
排序），问题栏是整个阶段的，不随轮次变。让轮次条横贯全屏等于说它也管着问题栏。

## 归属：接缝不动

`panel.js` 三千行，「新东西不再往里塞」那条还成立，而这次改动本来也不需要跨过
那条缝。缝的位置不变，只是两边从「互斥两屏」挪成「同屏两块」。

产物区是一块三态区，`data-mode` 一处说了算：`files`（默认）/ `graph` / `rubric`。
前两态归 artifacts，第三态归 `panel.js`。

**不用 `[hidden]` 切态**：`display: grid|flex` 会盖掉 UA 给 `[hidden]` 的
`display: none`，这个仓库为它流过两次血（`.round-progress`、`.graph-row`）。

标准放进宽的产物区而不是塞进窄的问题栏，是量出来的：`drawRubric` 每条标准是
`textarea rows=2` + 阻断勾选 + 删除按钮横排，上头还有三个角色按钮、scope 说明、
退休理由输入框、保存按钮。

## 顺手消掉的五份重复

原来弹层和驾驶舱各画一遍，现在每份只剩一个出处：

| 重复的东西 | 留下的那个 |
|---|---|
| 下一步（`#next-step` / `#stage-next`+`#stage-next-why`） | 动作带的 `#next-step` |
| 阶段名（`#sheet-title` / `#stage-name`） | 顶带的 `#stage-name` |
| 未决问题数（`#stage-gap-count` / 问题栏标题） | 问题栏标题 |
| 轮次标签（`#stage-round-label` / `#stage-timeline-summary`） | 轮次条的 summary |
| 判定章（`#stage-state` 的后缀 / `#sheet-mark`） | 顶带的 `#stage-mark` |

握手也跟着削到只剩真用得上的三个字段：`{changeId, phase, status}`。原来还传
`threadId` / `current` / `live` / `mark` / `openGaps` / `nextStep`，那边一个都没读。

## 星图按需建

星图默认不在屏幕上了。一进阶段就 `installScene()` 等于开一个 WebGL 场景在看不见的
地方转 —— 白烧电，而且 `setSize` 量的是一个还没有尺寸的盒子。改成按下按钮才建、
切走就 `dispose`。

## 高度：整页滚，一个滚动容器

这一处错了两次，两次是同一个错，值得完整记下来。

**第一版 `max-height: 44vh`**，理由是「动作带不许吃掉整屏」。在 945px 高的窗口上
它是 416px、内容 459px，只差 27px，看起来只是按钮稍微低了一点 —— 于是当时的"修法"
是把闸门那排 `position: sticky` 钉在带底，让题在下面滚。

**第二版把顶改成按剩余空间收缩**（`flex: 0 1 auto` + 下半屏 `min-height`）。

两版都在真窗口上崩了。720px 高的窗口、Build 那道题在等的时候：

| 版本 | 动作带 | 下半屏 | 症状 |
|---|---|---|---|
| `max-height: 52vh` | 374px | **81px** | 下半屏三个标题挤一起，一行内容读不到 |
| 按剩余空间收缩 | **155px**（内容 652px） | 300px | 连闸门按钮都在那条缝外面 |

而钉底那一改本身制造了一类新故障：一条不透明的横杠浮在会滚的内容上，**压住的
控件点下去什么也不发生**，和「按钮坏了」完全同形。命中测试当场抓到两个单选被
`stage-gates-row` 挡住。

真正的错在更前面：**拿一个和内容无关的数（视口比例、剩余空间）去限制一块高度
由内容决定的东西**。一道裁决最多十格，它有多高只有它自己知道。

定版：`#stage-view` 自己是**整页唯一的滚动容器**，动作带 `flex: 0 0 auto` 不封顶
不自己滚，下半屏 `min-height: 300px` 保住自己那份。不够就整页滚 —— 一个滚动条，
谁也不盖谁。闸门按钮排在题**前面**（它本来就短），因此永远看得见，也不需要浮。

整排一个按钮都不露脸时收掉整排。判据写在 `hidden` 上由 `syncGatesRow()` 维护 ——
`:empty` 那条选择器永远不匹配（元素里有缩进文本节点），是一条静默的死规则。

## 保住的那几条

每一条都是真机撞出来才有的，合并时一条没动：

- 答题表单只画在**它自己那个阶段**；旁路会话由 `clearStageActions()` 显式清空
  ——不清的话上一个阶段那排按钮会原样挂在旁路页上，按下去发的是别的阶段的动作；
- 题号写在 DOM 上（`form.dataset.question`），不是闭包变量；
- 进入阶段是**纯查看**：不自动拉起或聚焦 Terminal.app、不启动 turn、不推闸门；
- 退出恢复进入前的 Workspace 收起状态（`stageWorkspaceWasCollapsed`）；
- 轮次时间轴换行排布，任何轮数下都不出现横向滚动条；
- canvas 的 CSS 尺寸由样式表钉成 100%；
- 网页上仍然**没有也不许有 approve / reject**。

## 真机验到的（2026-08-17，用户跑着的面板，只读浏览）

1. DOM 里没有 `#sheet`；点环上的圆圈直接跑 `enter()`，工作区收起、阶段页上台。
2. 一屏上同时有：顶带、动作带（含五个闸门按钮）、闸门在看什么、轮次条、文件栏。
   没有「查看阶段产物」那个按钮了。
3. 两个副屏开关都能切能切回，`aria-pressed` 和文案跟着走。
4. 星图的 canvas 元素**按下按钮那一刻才出现**，切走后被 dispose。
5. canvas 的 CSS 尺寸 1064×381.5 = 容器尺寸（dpr=2），retina 两倍那个坑没复发。
6. 标准这一态：15 条标准 + 3 个角色按钮铺在宽栏里，轮次条按规矩消失。
7. `← 阶段环` 回到环，并恢复进入前的工作区状态。
8. 阶段页无横向溢出。

**1280×720 + 一道真题在等（2026-08-17 二次验证，定版之后）**：

- 逐个把控件滚到视野中央再做命中测试，**21 个控件全部命中自己，0 个被盖**；
- 动作带 653px（内容原样，没被压），下半屏 494px（高于 300 保底）；
- 整页一个滚动容器（1346 / 654）；唯一的嵌套滚动是文件正文那个阅读器，它不盖谁；
- 切 graph：canvas 884×448.195，与容器严丝合缝；切 rubric：15 条标准、场景已 dispose；
  切回 files 正常；来回切完再测一遍，仍然 0 个不可点。

### 验证方法本身的一个坑（2026-08-17 踩满一轮）

浏览器面板的标签被切到后台之后**不再合成**：CSS 过渡停在 `currentTime: 0`
（于是 `#stage-view` 的 `opacity` 永远是 0）、`innerHeight` 读回 0、`:hover` 一个
都不匹配、指针点击不落地。这些症状看着全像页面的 bug，其实一个都不是。

另外，被 `overflow` 裁掉的内容，`getBoundingClientRect()` 照样返回「排版上应该在
的位置」—— 拿它做命中测试会把「滚出可视区」误判成「被盖住」。

所以命中测试的正确姿势是：**先确认标签在前台**（`getComputedStyle(view).opacity`
是不是 1 就够判），**再逐个 `scrollIntoView` 到视野中央**，然后才 `elementFromPoint`。

## 没验到的

- **文件栏 / 正文栏装满数据的样子**：CHG-002 所属项目目录不是 git 仓库，
  `/api/stage-artifacts` 回 409 `not-a-repo`（库里既有的数据状况，与这次改动无关）。
  验到的是「投影不可用」那条路：检查台收起、文件栏占满。
- **一道真题从库里画出来**：CHG-002 现在没有待答的题。表单的排布是往 DOM 里塞
  假格子量的（横铺、钉底两条结论来自那次测量），没有走过 `/api/answer` 那条路。
  不去 `POST /api/ask` 造一道真题，是因为那会改用户库里的状态。
- **指针级命中**：浏览器面板的输入帧到不了被模拟成 1512px 的视口，处理器是用
  派发 DOM click 跑的；命中性另外用 `elementFromPoint` 单独证过（按钮中心点回来
  的就是它自己）。
