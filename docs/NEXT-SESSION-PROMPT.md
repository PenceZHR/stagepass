## 我要你先做的第一件事

**「跑这个阶段」按下去之后，界面几分钟一个字都不说。** 我以为它挂了。

实测它没挂 —— 一轮对抗真的在跑（`jobs.status = running`、三个 codex 进程活着、
`changes.status = running`）。问题是 `run()` 会 await 整轮，按钮停在「派发中…」，
而人盯着阶段环什么也看不见。

顺带记一条免得你白查：**`turns` 表是空的，那是正常的** ——
`RoundTurnRunner`（L6-1 接的那个）不写 turn 行，只有老的 `CodexTurnRunner` 写。

我要的是**跑一轮的时候人知道它在干什么**。至少能看见「红方在写 / 蓝方在挑 /
裁判在裁」走到哪一步了。怎么做由你判断，但有两条硬约束：

- **不许解析 pty 输出**（PRD §9.3，`architecture.test.ts` 第五条常驻护栏会红）。
  进度信号只能来自库或者进程状态，不能来自屏幕上的字。
- **别往阶段环那一屏加东西**（交接 §5.0 第 4 条）。答案在弹窗或左侧面板。

## 会浪费你时间的坑（今天全部实测过）

| 坑 | 事实 |
|---|---|
| **`grep` 不可靠** | 这环境是 ugrep，今天两次对确实存在的字符串返回空。**用 python 搜。** |
| **`str.replace` 静默失败** | 锚点不匹配就原样返回、不报错。今天栽四次，其中一次把文件从 1021 行变成 119 万行。**用 Edit 工具，或 python 的 `str.index`。** |
| **SQL 注释里不能有反引号** | schema 是一个模板字符串，一个反引号就提前结束它。 |
| **`.test.ts` 过类型检查** | 新树和老树相反，`tsconfig.src.json` 包含它们。 |
| **浏览器面板视口可能是 0×0** | 那时所有 `getBoundingClientRect` 都是垃圾，而且 `fit()` 会算出 1 列并真的发给 pty。先 `resize_window` 再量。 |
| **preview_start 起不来面板** | spawn 的 cwd 是 `/` 且不可读。用 Bash 后台起，再 `preview_start {url}`。 |
| **Codex 目录信任不继承** | 不从父目录继承，也不能用 `-c` 设。没被信任过的目录第一次跑会停在提示上。 |
| **`launchInto` 对活会话丢 argv** | 第二段提示词送不进去。要用 `PanelSessions.type`（打字），而且**文字和回车必须分两次写**——一次写会被当成粘贴，回车被吃掉。 |
| **Bash 里 curl 连不上 localhost** | 沙箱挡的。用浏览器工具验。 |

## 我对你的两条要求

1. **证据优先于报告。** 今天我至少两次先看了一个不相干的信号就下结论（库里
   `assessments = 0` 判成「模型没答」，其实答案在屏幕上；`ps` 里没有 `stagepass_ask`
   判成「没派发」，其实那次改成打字了压根不会出现在 argv 里）。**说「好了」之前，
   去验那个直接的判据。**
2. **改完 UI 必须在真浏览器里点一遍。** 今天有两个按钮的处理器指向了不存在的函数，
   411 个测试、typecheck、`node --check` 全绿，因为 `ReferenceError` 只在点下去那一刻
   才发生。`architecture.test.ts` 现在有一条护栏盯这个，但它只覆盖
   `addEventListener("click", () => fn())` 这一种写法。
