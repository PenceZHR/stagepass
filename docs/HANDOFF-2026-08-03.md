## 三、动手之前必须知道的（不知道会白改一天）

### 1. 闸门的判据是账本，不是进程

`sessions.has()` 问的是「注册表里还有没有这个阶段的 pty」，那是**当下这一刻**的事实；
而闸门要问的是「这个阶段有没有事情还没了结」，那只有账本知道（`JobStore.busyFor`）。

08-03 真机上这一条的三张脸：

- 一轮跑完、会话结束，而库里那个 job 还是 `running` —— 下一次派发畅通无阻，
  **同一个 (Change, 阶段) 上起了第二条裁判线程**。两条互相打断，一条烧掉近 300 万
  input token，人在终端里连字都打不进去。
- 问人的路超时之后 `return` 不关会话 —— 进程留着，这个阶段**每个动作都被拒**，
  而界面上没有杀掉终端的入口。**闭合死锁**：`brief` 说在跑、`run` 说没需求。
- 新提示词打进一个正在跑 turn 的会话，Codex 当成打断（`turn_aborted: interrupted`），
  人面前那个选择器被取消，返回空的 `cancel`。

**症状全都是「点了没反应 / 自己跳没了」。** 判据是 `mcp_tool_call_end` 的耗时：
被打断的那些 1~4 秒就返回，真人答的那次 53 秒。

### 2. 子 Agent 不继承 `-c` 传的 MCP server

2026-08-02 真机验的：子 Agent 的工具表 218 个，**一个带 stagepass 的都没有**；
但它有 `mcp__node_repl__*` / `mcp__openaiDeveloperDocs__*` —— 那两个在用户全局
`config.toml` 里。**结论：继承全局配置文件，不继承命令行 `-c`。**

**查工具在不在，必须把整张表倒出来自己看。** 差点栽的一次：探针问
`ALL_TOOLS.filter(x => x.name === "stagepass_ask")` 得到 `[]`，据此报「没有」——
那是问错了，绑定名是 `mcp__stagepass__stagepass_ask`。

### 3. 线程 id 是 UUIDv7，绝不能前缀匹配

前 8 位是时间戳不是随机数（`019fc396` 派生的孩子是 `019fc39f`/`019fc3a2`/…）。
`criterion_key` 那边是 `randomUUID()`（v4），两者不能混。

### 4. 客户端空文本格会吃掉回车

`optional` 也不管用。所以「选了选项就不用打字」只有在**第一趟里根本没有文本格**时
才是真的。整张表只能从最后一格提交，所以压轴必须是选项格。

### 5. 15 分钟那个截止时间现在可注入

`PanelOptions.askTimeoutMs`。写死之前，一条没按预期形状作答的测试会真的等满
（被框架 300 秒截断）—— 一次 `pnpm check` 从 33 秒涨到 20 分钟以上。
**写错的代价应该是 1 秒，不是 5 分钟。**

### 6. 老坑照旧有效

- Bash 的 `curl` 连不上 localhost（沙箱拦的）→ 用 Browser pane 的 `javascript_tool`
- `preview_start({name})` 起不来 → 后台 Bash 起进程 + `preview_start({url})`；
  **而且一个会话只开一次 tab，之后一律 `navigate`**（用户 08-03 明确要求）
- 改完代码要重启面板，**别在有轮在跑的时候重启**
- `ps` 会把非 ASCII 转义 → 从 rollout 读原文（我这一趟又踩了一次）
