## 三、还剩什么问题（按值不值得先修排）

### A. 一个字符的转写错误，废掉整份判定 ← 最值钱，今天量到的

Build 阶段 critic 那份**连续三轮全部作废**（12 条 `not_assessed`），死因是
`unknown_key`。裁判的原文：

```
RBC-3b0917a3-dedb-4f92-8dcb-3e4c49066895 yes …   ← 对
RBC-e783c97e-82ca-4c0b-7a698a980058      yes …   ← 少了一段（8-4-4-12，缺一组）
RBC-55dcfbe0-b48a-47c1-bc47-ccf6c9ba927c yes …   ← 对
RBC-2adf1324-5fc1-43a0-a24c-4a69a74d964f yes …   ← 对
```

**四条答得整整齐齐，一个 UUID 抄漏一段，四条一起扔掉。** 而且它连抄三轮 ——
那一轮轮次成功，不触发 detach，坏格式就在自己的历史里循环。

> **修法（我的建议，要先谈）**：把「不认识的 key」再分一层。
> 现在是「认识 / 不认识」二分，而**抄错**和**编造**是两件事：
> - 与某个已知 key **无歧义地近似**（唯一前缀命中、或编辑距离 1~2 且只匹配到一个）
>   → 当成那个 key，记一条「key 抄错了，已按最近的那条采纳」进 evidence
> - 匹配不到、或匹配到多个 → 照旧作废（编造仍要被挡）
>
> `RBC-` 后头 8 位十六进制在一份 rubric 里实际就是唯一的，前缀命中足够。
> **别直接放宽成「忽略不认识的行」** —— 那会让凭空多答一条重新变得无害。

### B. 模型能推翻人的驳回 —— 「以人为主」没被机制保住

`applyRound` 里 re-finding 一条 `closed` 的 gap 会**重开**它。对模型自愈是对的，
但今天实测：我用实证 dismiss 掉的条目，被下一轮蓝方原样重开（`QAB-001/002` 一次、
`QA-007` **三次**，跨了 QA→Merge 两个阶段）。

用户 2026-07-30 拍板过「人允许驳回蓝方的发现，**以人为主**」—— 那句话今天只在
一轮之内成立。

> 候选：人/操作员关掉的 gap 记一个来源标记，重开需要新证据；或者干脆进不可重开
> 名单，模型只能开一条新 id。**这条要先谈**，它动的是 gap 的核心不变量。

### C. 阶段之间没有「已裁定事项」的记忆

每个阶段一条新线程、新蓝方，它从零开始怀疑。今天同一个主题被反复重提：
**范围定义 3 次**（PRD/Spec/TechSpec）、**去重语义 5 次**（TechSpec 起每个阶段一次，
到 Fix 还在提）。每次都要烧一轮 + 一次裁决。

> 候选：一份「已裁定清单」随上游产物一起进任务书（和上游文档路径同一条路）。

### D. 蓝方无限铸币，对抗不收敛

每轮关 N 条、铸 M 条，纯靠轮次永远清不了零。今天能收尾全靠**批注钉死收口范围**
＋ 操作员裁决。没有人盯着的话，这个循环不会自己停。

> 候选：轮次预算；或要求新发现必须引用一条**尚未被覆盖**的验收标准。

### E. 报告类产物污染干净树

Review / QA / Merge / Retro 写文件但**不 commit**，下一个 `producesCommit` 阶段
（Fix）就被自己的上游产物拦在门外。这一趟我手动 `git commit` 入档 **5 次**。

> 候选：报告类产物由 StagePass 代 commit（和 Build 的 `commitAll` 同一条路）；

## 四、怎么验 / 怎么当操作员推流水线（照着做，别自己发明）

### 4.1 一次性库 + 一次性工作区（改代码时用）

```bash
V=.stagepass/verification/<你的名字>          # 被 gitignore
mkdir -p "$V/workspace"
node --import tsx scripts/panel.ts --port 4175 --db "$V/panel.db" \
  --change CHG-1 --project-name x --project-path "$(pwd)/$V/workspace"
```

### 4.2 推一轮（我这一趟全程用的那套）

**派发**（`/api/run` 要几分钟才回，所以只发不等）：

```js
// 在 Browser pane 的 javascript_tool 里，Bash 的 curl 连不上 localhost
fetch('/api/run?change=CHG-003', { method: 'POST' }).catch(() => {});
```

**盯库**（用 Monitor，别 sleep 轮询）：查 `changes` 的 phase/status、
最新 `jobs` 的 status/error、`gaps` 分组计数 —— 命中 `/settled` 或 `/blocked` 就停。

**裁决**（离线走状态机 + `respond`）：

```ts
new GapStore(db).replace(changeId, phase,
  respond(gaps.all(changeId, phase), {
    "GAP-1": { kind: "agree",   note: "下一轮照这个改…【操作员代批，待用户复核】" },
    "GAP-2": { kind: "waive",   reason: "接受这个风险，因为…" },
    "GAP-3": { kind: "dismiss", reason: "实证：…（要么裁判的依据，要么你亲手跑的）" },
  }).gaps);
new ChangeStore(db).apply(changeId, "reject" | "approve");
```

### 4.3 会浪费你时间的坑（照旧有效）

- **Bash 的 curl 连不上 localhost**（沙箱拦的）→ 用 Browser pane 的 `javascript_tool`
- **`preview_start({name})` 起不来** → Bash 后台起进程 + `preview_start({url})`
- **改完代码要重启面板**，而且**别在有轮在跑的时候重启**
- **跑一轮之前别进那个阶段的终端**
- **`ps` 会把非 ASCII 转义** → 从 rollout 读原文

| 事实 |
|---|
| **裁判会把一个 UUID 抄漏一段**，而 `unknown_key` 因此作废整份 —— 见 §三·A。 |

| **`-a never` 会让客户端对任何 elicitation 自动回 `decline`** —— 探针也别用。 |

| **`codex exec resume` 的横幅打的是父线程 id** —— 认线程只认 rollout 文件名。 |
