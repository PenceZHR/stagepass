# 流水

> **只追加。永不修改、永不删除、不需要维护。**
> 它记的是「当时」，不是「现在」，所以它不会过期。
>
## 什么时候写

不问「我惊讶了吗」——那是感觉，感觉判据必然退化。
问「**发生了下面哪件事**」，五条是「或」，中一个就写：

- 你删掉了今天自己写的东西
- 你对模型说了「不对，应该是…」
- 你查了一件你以为自己已经知道的事
- 你改了一条已经在 `BOUNDARIES.md` 里的线
- 你在两个方案之间来回了第二次

**兜底（挂在已有习惯上，不挂在情绪上）**：每次 commit 前扫一眼 `git diff`,
里面有没有今天写了又删的东西。git 本身就是现成的惊讶探测器 ——
写了又删 = 假设死了；同一文件今天第三次改 = 那条边界可疑。

> 这五条**不是清单，是校准器**。用两周会内化两三条，然后可以忘掉这张表。
> 任何要求你每天对照检查的东西，都会在第五轮死掉。

## 怎么写

> **写的时候不许打开别的文件。**

需要去查才写得出来，说明你在写总结不是写流水。总结是回忆，回忆是空的。

一格一行，写不下就是写多了。不许写「这为什么重要」、不许写结论、不许润色 ——
那些以后能重导。

## 怎么管住它 —— 唯一的整理动作

写之前 grep 一下：**这条像不像以前写过的。像就 `×N +1` 并追 it 号，不像才新起。**
十五秒。这是全套里唯一的「管理」动作。

**不要做**：建分类体系（写时要判断，且分类法三个月就漂）、定期整理（打卡，
第十轮会停）、周期性总结（总结是回忆，回忆是空的）。凡是为了整洁而付出的，
都会死 —— 整洁不是即时回报。

**重复才是信号。**出现一次可能是偶然，出现三次是结构性的 —— 而后者恰好是
你要的那份「全面认识」。这一个动作把平的流水自动变成按频次排序的列表。

白捡三样：

1. **转段扳机变成可读的数** —— 「同一个坑第二次」就是某条从 `×1` 变 `×2` 那一刻，
   不需要判断，看得见。
2. **M2 不需要整理** —— 那天只做一件事：按 `×N` 排序。前十条就是全部。
   剩下的还在，需要时 grep 得到。归并从「两天」降到「一次排序」。
3. **冻哪条边界有了依据** —— `×3` 以上多半是真边界，`×1` 多半是随手画的。
   和 `BOUNDARIES.md` 的「改过几次」互为印证。

> **丰富不是目标，可取回才是。**200 条流水加一次排序，比 20 份精心写的文档
> 有用一个数量级，因为后者每一份都在写可重导的东西，而且会过期。

## 写成什么样

**代词一律不许，具体名字写全。**每一格要能独立成立。

- ✗ 以为它会返回空 —— 它是谁？
- ✓ 以为 `thread/list` 会带 title

判据：半年后的你不看代码，只读这一行能不能明白当时发生了什么。

两种条目，前缀区分。写的时候不要停下来想属于哪类，随手挑一个：

```
假设死了 | it-NNNN | 我以为 X | 实际是 Y | 怎么发现的
否掉了   | it-NNNN | 考虑过 A | 选了 B  | 因为
```

再撞上同一件事时，**不新起一条** —— 在旧那条前面标 `×N`，把新的 it 号追上去：

```
×3 假设死了 | it-0042 it-0088 it-0131 | 我以为 X | 实际是 Y | 怎么发现的
```

`it-NNNN` 指回 `ITERATIONS.md` 里那条（日期在那边，不用重复写）。
**它是外键不是容器** —— 一条 iteration 可以产出 0 条、1 条、3 条；
一条 LOG 也可能跨三条 iteration 才浮现。想不起来是哪条就空着，别为它翻文件。
