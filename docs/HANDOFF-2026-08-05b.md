### 1. 许可门 —— 根因查明 + 解药接线（BACKLOG §2.1）← 最值钱

**它挡的不是某一轮，是「无人值守跑完一个阶段」这件事本身**，而这正是产品的立意。

根因早就清楚（每轮新会话 = 再弹一次），**缺的是有没有开关**。找到了：

```
$ codex -c 'mcp_servers.probe0.default_tools_approval_mode="bogus"' mcp list
Error: unknown variant `bogus`, expected one of `auto`, `prompt`, `writes`, `approve`
```

**拿假值喂配置解析器，让它把枚举吐出来** —— 这一招对任何 Rust + serde 的 CLI 都好使，
值得记住。

已接线：`pluginConfigFor` 加 `mcp_servers.stagepass.default_tools_approval_mode="auto"`。
走 `-c`，**只影响 StagePass 起的会话，用户的 `~/.codex/config.toml` 一个字不动**。

> **还没真机确认。** 判据：下一轮 rollout 里第一次 `stagepass_next` 是否紧跟
> `custom_tool_call_output`、中间没有等人的空白。**确认之前别把它当已解决**。

顺带解释了「Always allow 写在哪」那条悬案：`state_5.sqlite` / `codex-dev.db` 里
**没有任何审批表** —— 它可能压根不持久化，而正确的出路本来就不是那个按钮。

### 3. 两条棘轮护栏（BACKLOG §4.1）

分层护栏防住了「下层依赖上层」，**没防住「某一层长出一个吃掉一切的模块」**。补两条：

```
单函数行数        上限 300      例外表：panel-server.ts#handle = 1463
单模块依赖闭包     上限 60%      例外表：panel-server.ts = 92%（实测 91%）
```

**是棘轮不是干净上限**：现行违例钉进例外表、只许缩不许涨；另有一条护栏盯着例外表
不留死条目（修好了还留着，下一个人会以为它还是雷）。上限取「现状第二名再留点余量」
（函数第二名 279 行、闭包第二名 57%）——**不是审美数字，是「别再长出第二个 handle()」**。

用**真 TS 编译器**量函数边界，不用正则猜 —— 边界猜错一次这条护栏就静默失效。

### 4. CI（BACKLOG §4.6）

`.github/workflows/ci.yml`（push + PR）＋ `.githooks/pre-push`（`--no-verify` 留口子），
`package.json` 的 `prepare` 自动接 `core.hooksPath`。
**CI 只跑 `pnpm check`** —— 那是这棵树对「绿」的全部定义，不该有第二套。

### 5. 会话尸检（BACKLOG §2.2，用户裁的红线）

起来 5 秒内非零退出 → 把它吐出来的**头 512 字节原样写 stdout**。

**`process.stdout.write(bytes)` 直写，全程不变字符串** —— §9.3 那条护栏盯的是
`toString`/`TextDecoder`，所以一个豁免都没开。阈值 5 秒不是 1 秒：EPERM 那类不一定
压着 1 秒线，而 5 秒内退出的 codex 无论如何都不是正常收工。

### 6. `panel.js` 上类型检查（BACKLOG §4.7）

35 → **0** 错误，`tsconfig.panel.json`（allowJs + checkJs）接进 `pnpm typecheck`。

关键手法：`pick/button/field/dialog` 四个取元素的助手 —— **在声明处一次收窄**，
`.disabled`/`.value`/`.showModal()` 不必在 30 个使用点各写断言；顺带 `pick` 取不到
就抛并说出是哪个 id（原来是运行时 `null.textContent`）。

### 7. 派发不再阻塞 + 只绑回环（BACKLOG §3.4）

- **派发排完队就返回**，回执带 `jobId`；轮在后台跑完并收尾。原来 `await loop.runOnce`
  要等整轮，而实测一轮 60~343 分钟 —— 浏览器和代理会先超时，那时人看到「网络错误」
  而轮跑得好好的。**后台那段兜住一切异常**：移出 HTTP 之后没人接的 rejection
  会被 Node 直接杀进程，把面板整个带走。
- 前端不再说「跑完了」，改说「**派出去了，正在跑**」—— 说错这一句就是让人以为
  可以去裁决了。
- `listen(port)` 不带 host 时 Node 绑**所有网卡**，而这面板能派轮、改 rubric、
  删 Change、往跑着 Codex 的 pty 写字节。现在绑 `127.0.0.1`。
  **鉴权本身仍没做**（用户数 1 是设计），但「不做鉴权」和「向全网段开放」是两件事。

### 8. 结果契约走文件（BACKLOG §3.4）

## 二、我自己造的一次回归，已修 —— 这条最该读

给 `FitAddon` 写声明时我写成 `declare class`，然后**为了迁就声明去改运行时代码**
（`new FitAddon.FitAddon()` → `new FitAddon()`）。

```
pnpm check     784 / 784 全绿
typecheck      0 错误
浏览器里       FitAddon is not a constructor  →  顶层执行中断  →  环一个节点都画不出来
```

真实形状是命名空间对象，构造器在 `FitAddon.FitAddon` 里。

> **① 声明是描述现实的，不是规定现实的。** 打架时改声明。
> **② 类型检查替代不了「在浏览器里打开一次」。** `.d.ts` 里的 `declare` 是断言，
> 编译器只会相信它，不会去核对。

**排查手法记下来**（下次快得多）：症状是 `load()` 报
`Cannot access 'phases' before initialization` —— 一个 TDZ 错误出现在**函数全都存在**
的时候，就说明顶层执行在声明那一行之前中断了。函数声明会提升，`let` 不会，
**这个不对称正好指出了中断点在哪**。

修完实测：11 个节点、2 项目、当前 Build、进度 45%、终端挂载、零 console 错误。
