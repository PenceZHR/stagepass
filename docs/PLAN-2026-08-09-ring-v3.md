## 一、环的定稿(v3)与每条决定的理由

```
PRD → Spec → Arch ─┬─ BuildPlan → Build ─┬─ QA ──(闸门放行 = closed)
       (人深度介入)  └─ TestPlan  → Test  ─┘  ▲
                     (互盲,落点围栏)     机器装订案卷
```

**八个阶段**:PRD、Spec、Arch、BuildPlan、TestPlan、Build、Test、QA。
并行的照样是阶段,环上全部画出来。

### 逐条决定(用户 2026-08-09 拍)

1. **BuildPlan ∥ TestPlan、Build ∥ Test,两条对称轨道**。每轨「先文档后代码」。
   两轨在 Arch 契约之下互盲:Build 看不见测试,Test 看不见实现。
   理由:测试若读了施工方,就继承施工方的盲区 —— 放大哲学的独立性前提
   (串供的一致什么都不是,互盲的一致才是信息)。
2. **Review 不再是阶段** —— 蓝方就是阶段内 review,全环统一,代码阶段不例外。
   旧 Review 阶段的任务(读 diff、攻击逻辑与契约)由 QA 收编。
3. **Fix 不再是阶段,是一个交互** —— 打回(sendBack)重开目标阶段,修复就是
   重开阶段的下一轮。环 UI 上用打回箭头/重开座位表示,不占站位。
   `SENDS_TO_FIX`、returnStack 的 Fix 特例整套拆除 —— 通用机制吃掉全部特例。
4. **Merge / Retro / Done 不是阶段**。判据:阶段的入场券是「有产物可对抗」。
   - Merge 的产物是 git 动作 → 守卫已有机械形式(pre-push「绿过」印章,67883ad),
     动作本身归人,在自由终端做。
   - Retro 是自审,内容结构上不许承重 → 真复盘是 gap 账本 + 判例修 rubric 回路。
   - Done 是状态不是工作 → QA 闸门放行即 `closed`。
5. **QA 是对撞点**,消费机器装订的案卷,三攻:**读**(旧 Review 的活)/
   **跑**(执行 Test 轨的测试)/**变**(三方向变异检验测试成色)。
   打回三向归因:代码错 → Build、测试错 → Test、契约错(共模)→ Arch(升级到人)。
6. **案卷由机器装订,不许由模型撰写** —— 被告不许给检察官写案情摘要
   (转述定律的第五张脸,预防性封死)。固定 schema,commit id 从库取(手抄禁令)。
7. **Arch 人深度介入**:两轨都从 Arch 推导,Arch 的错误是共模失效,对撞检验
   在原理上抓不住它 —— 分叉点就是共模点。机械形式复用 brief 那条规矩:
   **模型起草,人改,未经编辑不算 settle**(编辑过门)。
8. **改名走退休,不走 rename**:`Plan` 退休、新增 `BuildPlan`;`Test` 从 TestPlan
   拆出(TestPlan 收窄成纯文档阶段)。历史行照旧读得出。

## 二、分批

每批一个闸门:`pnpm check` 全绿 + 批内新增行为有测试钉住。底层先行,
上层等下层绿了才动(层间闸门)。

### 批 1 · 域层地基(最承重,先行)

`phase.ts`(PHASES 增 BuildPlan/Test、退休名单扩到七、DEFAULT_GRAPH 八阶段、
`TERMINAL_PHASE = "QA"`、CONSUMES 定稿、`PRODUCES_COMMIT = {Build, Test}`、
删 `SENDS_TO_FIX`/`sendsToFix`、`RED_REVIEWS_OTHERS = {QA}`)+
`change-state.ts`(拆 Fix 特例:reject 不再进 Fix,QA 闸门放行 → closed)+
`journey.ts` 投影跟上 + 全部受影响测试。

### 批 2 · 剧本与模板

`phase-play.ts` / `phase-template.ts` / `rubric-defaults.ts`:BuildPlan 继承 Plan
的模板与标准(逐条过一遍措辞);TestPlan 模板收窄成纯文档(用例映射、怎么跑、
哪些必须过);**Test 阶段新模板**(测试代码 + 落点声明);**QA 新剧本**
(案卷输入、读/跑/变、三向归因的选项)。改完 `node --import tsx
scripts/dump-rubrics.ts` 再生成文档。

### 批 3 · 运行层与库

`round-turn-runner.ts`(上游文档投递按新 CONSUMES;Test 的 commit 语义)+
`schema.ts`(CHECK 约束扩名;**迁移先、SCHEMA_SQL 后,封在 prepareSchema 里**
—— 建表顺序陷阱)+ 活库迁移验证(CHG-001 在 Arch/settled、returnStack
["Build"],v3 下要原样可读可走)。

### 批 4 · 并行与隔离(重开原批 3)

案 B 对称化:TestPlan/Test 窄提交(声明落点),Build 保持 commitAll +
提交前挡门(dirtyPaths ∩ 对方声明落点 → blocked 报人)。座位审计的 5 条 P0
逐条修(worklist 按 (Change, 阶段) 分队列、孤儿座位、blocked 座位出口、
sendBack 不收编 settled 座位、closed 不开座位)。`serveParallel` 撤回解除。
分叉调度:Arch 过门 → 开 BuildPlan + TestPlan 两个座位;合流:Build 与 Test
都 settled + 过门 → QA 开场。

### 批 5 · 案卷装订 + QA 三攻

QA 入场时 StagePass 从库拼案卷(固定 schema:Arch 契约节、两份 plan、两个
commit id、两份报告、怎么跑)。QA 剧本接案卷。变异攻击的机械部分
(no-op 仍绿 / 还原必红)进 QA 的 rubric。

### 批 6 · Arch 编辑过门

复用 brief 的「未经编辑不算」:Arch 的产物没有人的编辑痕迹就不许 settle。
轮中介入渠道(旁路提问、elicitation)照旧。

### 批 7 · UI

环的钻石画法(并行座位并排)、Fix 交互(打回箭头/重开座位的表示,不占站位)、
自由终端(closed 后挂载;只读原则:看状态不起进程)、退休阶段的历史显示。

### 真机验收(贯穿)

每批离线绿之后,批 3 起要用户真机各验一次;批 4 的 git index 锁、挡门噪音
只有真机能答(设计文档末尾两问)。

## 三、明确不做的

- 不做 DAG 图 —— 主线保持全序,并行走座位层。`sendBack`/`upstreamOf`/
  `returnStack` 的地基一根不动。
- 不做字符串 rename —— 历史行的名字永不改写。
- 不做模型写的「总结文档」喂 QA —— 案卷只许机器装订。
- 不动「网页无 approve/reject」「不解析 pty」「不许 exec」三条铁律。
