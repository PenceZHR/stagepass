# StagePass 交接 · 2026-08-18

**一句话**：整套 StagePass UI 可以搬进 Codex App 里渲染——这条路当晚被实测走通了
（Codex 主动来取我们的 HTML 并整块画出来）。终端驱动那条路也全部验通并写成了代码，
但它做不成产品形态，退居为自用工具。

> 本文分「**实测**」和「**推断**」两类，凡是从二进制字符串挖出来、没跑过的一律标注。
> 上一份交接（08-17）里对 MCP 卡片的判断当晚被推翻，见 §四。

---

## 一、这一夜的定案

**形态**：StagePass 做成一个 **Codex 插件**，UI 作为 MCP 资源在 Codex App 里渲染。

```
plugin.json          插件身份 + interface（名字/图标/分类/默认提示词）
skills/              八阶段题面、rubric 正文        ← 软（模型读）
.mcp.json → server   状态回程 + 阶段推进单入口工具   ← 半硬（单入口）
hooks（PreToolUse）  判据没过就 deny                ← 硬（宿主执行）
ui:// 资源           打包好的整个面板                ← 在 App 里渲染
```

**三条支撑判断**

1. **闸门要守「状态迁移」，不守「写操作」。**
   实测：一个不知情的子 Agent 的 `Write` 被拒后，**改用 Bash heredoc 绕过去成功了**。
   文件系统有一千个入口，`stagepass_advance` 只有一个，且阶段状态在库里不在磁盘上。
2. **判据层已经是干净的。** 量过：`src/domain/` 对引擎依赖为 **0**；耦合全在
   `src/web`（5 个生产文件）和 `src/work`（1 个）。换引擎不用改判据。
3. **只依赖能正常升级的东西。** 依赖一个有 changelog 的库（SDK / 插件面）是正常工程；
   逆向没有版本号的内脏（`le32-json` 私有 IPC、`state_5.sqlite`）不是。
   当晚一度把目标推成「零版本耦合」，推到极致是 AppleScript + tty——技术上最稳，
   **但那是自用黑活的形态，不是产品**。目标已修正。

## 二、真机验过的 —— Codex 插件路线（最终方向）

环境：`codex-cli 0.147.0`（CLI）/ `0.148.0-alpha.15`（App 自带，`codexHome` 相同）

### 已跑通

| 事实 | 证据 |
|---|---|
| **Codex App 会渲染 MCP 资源里的 HTML** | `resources/read` 被调用 1 次；内容整块、全宽出现在对话流里 |
| 本地插件能装、App 能看见 | `codex app-server` 的 `plugin/list` 返回 `stagepass@stagepass-local installed=True enabled=True` |
| 插件的 MCP server 自动加载 | 裸 `codex`（无任何 `-c` 覆盖）启动即收到 `initialize`/`tools/list` |
| **iframe 外部源被沙箱挡** | Codex 进程**确实连了** `127.0.0.1:4173`，渲染层显示 `This content is blocked`。<br>**不是面板的锅**——面板一个 frame 阻挡头都没设（实测响应头只有 content-type） |
| `elicitation mode:"url"` 是死路 | 格式对（四字段全必填），**TUI 和 App 都回 `{"action":"decline"}`** |

### 确切配方

```
插件根/
  .codex-plugin/plugin.json     name version description mcpServers skills interface
  .mcp.json                     {"mcpServers":{"x":{"command":"node","args":["./s.mjs"],"cwd":"."}}}
  server.mjs
  assets/app-icon.png

interface 的真实字段（抄自 bundled 插件）：
  displayName shortDescription longDescription developerName category
  websiteURL privacyPolicyURL termsOfServiceURL logo defaultPrompt brandColor screenshots
```

**本地 marketplace**：根目录必须有 **`.agents/plugins/marketplace.json`**

```json
{ "name": "…", "interface": { "displayName": "…" },
  "plugins": [{ "name": "…", "source": { "source": "local", "path": "./plugins/…" },
    "policy": { "installation": "AVAILABLE", "authentication": "ON_USE" }, "category": "…" }] }
```

`authentication` 只接受 `ON_INSTALL` / `ON_USE`。装：
`codex plugin marketplace add <路径>`（名字由路径推，**没有 `--name`**）→ `codex plugin add x@<市场>`

**渲染**：工具在 `_meta` 里声明 `"openai/outputTemplate": "ui://…"`，server 实现
`resources/list` + `resources/read` 返回 HTML（`mimeType: "text/html+skybridge"` 可用）。

**特性开关名是 `enable_mcp_apps`**（不是 `mcp_apps`，后者报 `Unknown feature flag`）。

### 三个会咬人的坑

1. **App 启动时缓存插件列表。** 装完插件**必须完全退出重开**（⌘Q），否则列表里没有。
   「完全看不到插件」当晚就是这个原因。
2. **`app/list` 不是本地插件列表**——它是远程 connectors，未登录时 403。要用 `plugin/list`。
3. **调试利器**：`codex app-server` 起来后发 `initialize` → `plugin/list`，
   能直接问出 **App 侧**看到的插件清单，不用开 App。

## 三、真机验过的 —— 原生终端路线（已搁置，但代码可用）

这条路当晚全部验通，代码已落在 `src/seat/`。**它稳，但它是自用工具不是产品**（macOS +
Terminal.app 独占，分发不了）。留着当第二个引擎实现。

### 配方

```
开    : do script "cd '<座位目录>' && codex"   → 立刻记下 tty of t
送    : do script "<题面>" in <tab>             ← 先查活性
提交  : do script "" in <tab>                   ← 必须单独一次，文本自带的 \r 不提交
读    : history of <tab>
关    : close window → 轮询到释放（异步！）
重连  : do script "cd '<座位目录>' && codex resume --last"
```

### 实测结论

| | |
|---|---|
| 绑定 | **靠座位目录，不需要任何 thread id**。`resume` 默认按 cwd 过滤，一座位一目录即唯一 |
| 端到端 | 存暗号 → 关窗 → `resume --last` → **不提暗号它自己想起来** ✓ |
| 多座位并发 | 两个座位各自 resume，**零串扰** ✓ |
| 归档 | 归档过的会话被 `--last` **自动跳过**——旧的「绑定线程被归档」整类消失 |
| 长题面 | **12,780 字节 / 65 行中文完整到达**，多行不拆成多次提交 |
| 审批 | **会阻塞**，屏幕上认 `Press enter to confirm` |
| 把手 | **用 `tty`**——`custom title` 会被 codex 反复冲回 git 根名 |
| 读屏 | 用 `history of t`；`contents` 撞 AppleScript 解引用运算符 |

### 一个真危险

关窗后 codex **不会立刻退**。3 秒后 `resume` 撞 `already has an active writer` → codex 退出
→ **之后送的题面被 zsh 当命令执行**（实测 `zsh: command not found: 把你记得的暗号…`）。

**两条安全闸门已写进 `src/seat/`，不是优化是必需**：
送之前查 `(processes of tab) contains "codex"`，不含就拒发；关窗后轮询到 `ps -t` 无 codex 才 resume。

## 四、被推翻的旧结论

| 旧的 | 新的 |
|---|---|
| 「MCP App 从未运行过 / 卡片不渲染」（07-28） | **成因是用错了路径**：mcp-server 自己起 turn → 卡片不渲染；<br>而且 `enable_mcp_apps` 从没开过。**人拥有 turn + 开关打开 → 渲染成功** |
| 「面板可以 iframe 进 widget」 | ❌ 沙箱挡外部源，**面板必须打包成资源内容本身** |
| 「`elicitation mode:"url"` 是画布」 | ❌ TUI 和 App 都 decline，**这条路是死的** |
| 「每轮弹一次 MCP 许可门」 | 那是**每轮新会话**造成的。长活会话 = 一个会话按一次 |
| 「`src/domain/` 完全零耦合」 | 生产代码是 0，但 `domain/turn.test.ts` 和 `rubric-defaults.test.ts` **的测试**引用了 codex |
| （本次会话内自我更正）「1KB 静默截断」 | 假象，是读日志比字节到达快。26KB 完整 |
| （本次会话内自我更正）「回车会替你批准操作」 | 不存在。那次审批是用户自己按的 |

## 七、还没验的（按重要性）

1. **`window.openai` 桥的真实 API** —— 决定搬进去的面板能不能交互。
   App 的 `app.asar` 里挖到了 `requestDisplayMode` / `displayMode` / `callTool` /
   `setWidgetState` / `sendFollowUpMessage` / `maxHeight`，显示模式枚举有
   `fullscreen` / `inline` / `pip`。**全是字符串挖的，一个都没实测。**
   探测 widget 已写好并装上，只差在 App 里点一次。
2. **全屏能不能真的铺满** —— 同上，`requestDisplayMode({mode:"fullscreen"})` 未验。
3. **three.js 能不能在 widget 沙箱里跑** —— 决定 3D 图谱能不能进去。
4. **widget CSP 允许哪些外部资源**（字体、图片）—— 决定要内联多少东西。
5. Codex 的 **hooks TOML 确切写法** —— 字段名从二进制挖到了
   （`HookEventsToml` / `matcher` / `enabled` / `trusted_hash` / `handler_type` /
   `execution_mode` / `source_path`），事件名齐全（PreToolUse / PermissionRequest /
   PostToolUse / PreCompact / PostCompact / SessionStart / SessionEnd /
   UserPromptSubmit / SubagentStart / SubagentStop / Stop）。
   二进制里有 `Command blocked by PreToolUse hook:` —— **能拦**，但配置怎么写没验。

## 八、下一步

**如果 §七.1 三条全绿**（桥有 API / 能全屏 / callTool 闭环），路线是：

```
panel.html + panel.js + CSS  --esbuild-->  一个自包含 HTML
        ↓
MCP server 的 resources/read 返回它
        ↓
在 Codex App 里全屏渲染
        ↓
所有 fetch('/api/…')  →  window.openai.callTool(…)
```

**不开浏览器，不要面板服务器。**

**如果桥是死的**（widget 纯静态），那「整套 UI 进 App」只能做到「只读展示」，
交互仍要回到面板窗口——那时候要重新在「不可能三角」里选。

## 附：其它路径的调研结论（当晚都走到了尽头）

| 路 | 结论 |
|---|---|
| Claude Code 插件 | 面齐全（skills/agents/hooks/MCP），**钩子能真拦**（实测 `PreToolUse` deny、`Stop` block）。但**CLI 子进程拿不到登录态**，沙箱内外都是 |
| Claude Agent SDK | 形态最匹配「StagePass 是界面」，状态是 typed 消息流（十几种），审批是 `canUseTool` 回调，会话能 rename/tag。**但要 API key 计费，且明确禁止用 claude.ai 登录** |
| Codex SDK | `@openai/codex-sdk`。事件粒度粗（`item.completed`/`turn.completed`），**审批没有回调位**。但 `outputSchema` 是一等公民 |
| Managed Agents | Outcome + rubric + 独立裁判循环 = 环 v3 的核心机制，**已经是产品功能**。但沙箱托管在 Anthropic，本地仓库别扭 |
| DeepSeek Harness | 架构逐条对上（`agent/pre-step` 能 reject、UI 是 bundle、agent loop 可换）。**但发布五天，官方全大写写着 THERE WILL BE COMPATIBILITY-BREAKING CHANGES**。形状对，时机不对 |
| TUI 里嵌多个 codex | ❌ 要自己写终端复用器（= 重做 tmux）。且原生 Terminal **无法用 AppleScript 新建标签页**（`make new tab` 失败、`do script … in window` 不新建） |
