**治法（今天已做完并真机验过）**：模板把散文切成有限个格子、rubric 挂到节上、
设计阶段的反方收口到逐条判定。**结果见 §二。**

## 二、今天做完的（十六次提交，`pnpm check` 1046 全绿）

### 2.1 机制

**两个判据，两件事，别混**：

| 判据 | 管谁 | 后果 |
|---|---|---|
| `templateFor(phase) !== null` | **红方** | 必须照节写；缺节开 `TEMPLATE-<节>` 挡门 |
| `PHASE_PLAY[phase].blue.investigates` | **反方** | 够得着代码的才交自由 blockers |

十份模板（PRD 7 节、Spec 5、TechSpec 6、Plan 5、TestPlan 6、Build 6、Review 5、
QA 5、Merge 4、Retro 4），rubric 按节铺开，**挂了节 ⟺ 出厂就阻断**。

### 2.2 实测账（**这套机制唯一的证据**）

| 阶段 | 轮 | 判定 | `no` |
|---|---|---|---|
| PRD | r6 | 17 | 0 |
| Spec | r2 | 12 | 0 |
| TechSpec | r1 → r2 | 12 → 12 | **1 → 0** |
| Plan | r1 | 9 | 0 |
| TestPlan | r1 | 11 | 0 |
| **Build** | **r1** | **18** | **7（全部指向同一个事实）** |

**七轮有效对抗：`finding` 累计 0，模板缺节累计 0。** 对照三刀之前的 Build：
r2 开 35 条、r6 开 21 条。

> ⚠ 上一份取证（21 轮 / 139 条）**已被删除且不可恢复**。这一份是唯一的了，
> **动地基之前先导出来**。

### 2.3 两个「红方赢不了」的标准，是真机逼出来的

单元测试永远抓不到它们——它们不是「代码错了」，是**要求了一件结构上做不到的事**：

1. **模板漏了「已经定死的约束」那一格** —— 红方把技术栈写哪儿都判 no
2. **收走了反方的 id 通道，却没回头看哪条标准在要它**

由此立下的对称规矩：**放开一样能力要看有没有标准在禁它；收走一样能力，要看有没有
标准在要它。**

## 三、十二阶段重定义（用户 2026-08-06 拍）

### 3.1 新形状

```
PRD → Spec → TechSpec → Arch → Plan → TestPlan ∥ Build → QA → Merge → Retro → Done
                                                     └── Review / Fix 挂在 Build 上
```

**十一个状态 + 两个联动。** 判据：**这个阶段的产出，是它自己的，还是关于别人的
产出的？**

- **状态**：产出是它自己的，有闸门
- **联动**（Review / Fix）：产出是「关于 Build 那份代码的」——它们不是 Change
  去的地方，是**发生在 Build 上的活动**

### 3.2 Build 里的分工

```
红方    写代码，**看不到测试源码**
蓝方    **红方写完之后**跑 TestPlan 交的测试 → 反馈「哪条失败、输出是什么」
Review  全程盯：审代码，也审测试代码本身对不对
Fix     红方响应意见继续改 —— 那是下一轮，不是新阶段
```

**这个设计翻掉了 BACKLOG §8.8**，而且更强：§8.8 反对「Build 不许看测试」的理由是
「看不见会退化，模型可以猜」——**而蓝方去跑，红方拿得到「哪条失败、输出是什么」，
那是对着一个不可见的判据做 TDD，不是猜。**

### 3.3 新增 Arch

它给 BACKLOG §5.5 那条反馈链路第一次提供落点。§5.5 写着「要新增图上没有的依赖边
就停手，**攒进架构那一批**」——而今天没有那个格子。

模板草案四节：**动哪几个模块 / 新增哪些依赖边（每条写为什么非加不可）/ 边界划在哪 /
想过但没选的划法**。第二节就是那条分界线的落点。

> ✅ **位置已拍（2026-08-06 晚）：TechSpec 之前** —— 先划骨架再填数据。
> 新主线：`PRD → Spec → Arch → TechSpec → Plan → TestPlan ∥ Build → QA → Merge → Retro`。
> TechSpec 在既定模块边界内写数据和接口，Arch 的产出约束它。

## 四、地基：把「阶段」从唯一的组织维度降级

三类诉求挂不上今天的模型，**一个根**：

| 诉求 | 挡在哪 |
|---|---|
| Review/Fix 联动、TestPlan ∥ Build、Plan ∥ TestPlan | `ChangeState.phase` **是单数** |
| **先闲聊再 PRD** | 同上，且没有「阶段之外」这个概念 |
| **中途开窗口问名词** | `change_bindings` 按 `(change, phase)` 建键——**会话必须属于某个阶段** |

目标：一个 Change 上同时有**状态 / 联动 / 旁路会话**三样，各自有生命周期、互不占座。
数据模型四处改动见 `DESIGN-phase-not-the-only-axis-2026-08-06.md` §三。

## 五、分批执行（**每批单独可验收、可回滚**）

### 批 0 · 修投递层 —— **不动地基，先做这个**

`HANDOFF-2026-08-06.md` §5.5 那五条：

1. 裁决完成后 Codex 会话不关 → 下一阶段起轮认不出自己的会话
2. 出口按注册表判，而进程不在注册表里 → **出口被藏，人一个能按的都没有**
3. 页面轮询死了不自愈 → 重启面板后永远冻在旧状态
4. `retry` 之后错误信息是旧的 → 人看到的原因是假的
5. 拒绝的理由不上屏 → `runRound` 返回了 `dirty` 列表，界面不显示

**为什么排第一**：今天七个阶段里对抗机制**一次没出过错**，而**每一次卡住都是这五条**
（超时白烧 73 分钟、会话冲突、出口消失、retry 空转）。地基改动要跑很多轮才验得完，
现在每一轮都在交这个税。

**共同的形状**：不是「状态错了」，是**状态对的、但人看不出发生了什么**。修任何一条
之前先想清楚：**这件事该在哪一屏告诉人。**

**验收**：连着跑三轮不同阶段，一次都不用手动 kill 进程或改库。

### 批 1 · 旁路会话 —— **不动状态机**

`change_bindings` 加 `kind: round | aside`，`phase` 可空；`phaseBusy` 只数 `round`。

**验收**：一个阶段正在跑轮的同时，能开一个窗口问名词，两边互不干扰。

**批 0 + 批 1 加起来，「一条路走到黑」这个体感当场消失，而且一行状态机都不碰。**

### 批 2 · 闲聊 → brief

闲聊就是旁路会话的第一个用户。**模型起草、人改**（已拍）。

难点是那条机械判据：**未经人编辑的草稿不算 brief** ——
直接接受模型草稿等于没改，`round-turn-runner` 那句「人要的是这些，他自己答的，
不是模型猜的」就成了假话。

**验收**：新建一个 Change，谈十分钟，brief 是几百字而不是 9 个字（今天实测值）。

### 批 3 · 多状态

`ChangeState.phase` → `change_states`。先做**只读兼容层**（`state.phase` 保留为
主状态的派生 getter），再逐个迁调用点。

> ⚠ **这一批一动，§2.2 那份实测账全部作废。先导出来。**

**验收**：TestPlan 和 Build 同时 active，各自跑轮、各自有闸门、互不打断。

### 批 4 · 联动

Review / Fix 从 `PHASES` 摘出来 → `change_activities`；`returnStack` 退休
（**它记的本来就是关系数据**，只是被塞进了位置字段）。**QA 不动**——它仍是状态。

**必须在 Review 真跑过至少一轮之后做**——它要建的形状有一端从没在真机上出现过。

**验收**：Build 上挂着一个 open 的 review 联动，红方改、蓝方跑、Review 盯，
人只在 Build 出口表一次态。

### 批 5 · Arch + Build 分工

加 Arch 状态；TestPlan 只交方案和代码、自己不跑；Build 红方看不到测试、蓝方跑。

> ⚠ **要先撤掉今天给 TestPlan 加的「实际跑出来的结果」那一节** —— 它是按
> 「TestPlan 跑在 Build 之前」做的，和这一批冲突。

**要先拍 Arch 的位置。**

## 八、判断原则：**AI 的软开和人的不一样**

> 用户原话：「整体流程差不多，但是**很多细节是完全不一样的**。」

这张表是给下一轮看的——**不要按「正常软件流程」把这些细节简化掉**：

| 人怎么做 | AI 必须怎么做 | 证据 |
|---|---|---|
| 不会在 PRD 里追「13.0 的词法形式」 | **模板 + rubric 硬约束边界** | PRD 四轮同一句抱怨在降尺度 |
| 「别自己审自己」是常识 | **必须是机械闸门** | Build 自己写 `verify.mjs`，关一个绕过点长一个 |
| 评审是连续的 | **必须离散化才收敛** | 139 条 finding vs 17 条判定 |
| 不懂就问 | **不懂会编** | 所以要旁路会话 |
| **架构在脑子里** | **写不下来就不存在** | 所以 Arch 要有产出、有闸门 |
