## 1 · 定位

**一句话**：在决定的那一刻，给你本来看不见的东西；在决定之后，留住你为什么这么定。

### 1.1 三层，载体各不相同

| 层 | 在哪 | 原子 | 归谁 |
|---|---|---|---|
| **执行** | Codex / Claude Code | session | 不归你管了 |
| **留存** | markdown + git（**客户端之外**） | 文件 | 代码 + 你 |
| **看** | 面板（只读）+ `sp` 命令 | —— | 代码 |

### 1.2 不做什么

不派轮、不开会话、不驱动 turn、不做无人值守、不做多人、不拦危险操作。

### 1.3 唯一不会被工具吸收掉的那块 【推理】

判据是三条同时成立：**跨会话 · 全量视野 · 不是模型**。

Codex 三条都不满足——不是它不够强，**是它一次性**。一个 session 看得见它上下文里的东西，
仅此而已。没有任何东西在六个月的尺度上盯着你的档案。

## 2 · 原子：session

### 2.1 为什么是 session 不是 iteration 【推理】

**归档的最佳时机，就是上下文即将永久消失的那一秒**——而那正是 session 结束。

iteration（一段反馈 = 一条）语义更准，但要你手动划；session 由客户端划好，**免费**。
免费的粗粒度赢过要手动维护的细粒度——后者不会被维护，那就等于不存在。

顺带：**你已经跑了两个月了**，`docs/HANDOFF-*.md` 二十多份就是 session 粒度的归档，
只是没起名字、没固定格式。所以这不是新赌注，是把已有行为形式化。

### 2.2 硬规矩

1. id 来自客户端，**不手抄**
2. 已被引用的 id 冻结，不合并不拆分
3. 粒度可以严重不均匀——**它是地址，不是度量单位**
4. 被迫换 session（上下文满）也是一条，而且**那种最该记**

### 2.3 代价，说清楚 【推理】

session 边界 ≠ 信息边界。一个 session 可能含五段反馈；一件事可能横跨两个。
所以是多对多：一个 session 产出 0..N 条 LOG，一条 LOG 可能跨两个 session 才成形。

## 3 · 产出：封闭集合

**封闭是必须的**——地址指向的东西不确定，追溯就断了。

### 3.1 必产两样

| 产出 | 作者 | 为什么 |
|---|---|---|
| **原话**（session 开头的声明 + 你的反馈） | 人 | 不可重导。原样粘贴，成本为零 |
| **实测结果**（成 / 部分 / 没成 / **没测**） | 人 | git 显示改了什么，不显示改完管不管用 |

> **「做了什么」不是必产**——可重导，`git diff` 里全有。写它是给自己造二手资料。
>
> **`没测` 是合法值，而且是最重要的信号**。连续十条 `没测` = 你停止接触现实了。

### 3.2 可选四样，各 0..N

commit 引用（**代码从 git 抓，不许 AI 报**）· LOG 条目 · 边界改动 · 赌注变化

**大部分 session 产出 0 条 LOG——这是对的，不是漏。**

### 3.3 AI 登记什么 【推理】

**只登记它独有的那部分**（LOG 那三样）。碰了哪些文件、几个 commit、时长，全部代码自算。
AI 报文件清单会漏、会美化。

## 4 · 留存：四份文件

| 文件 | 单位 | 性质 |
|---|---|---|
| `BETS.md` | 一条赌注 | 会改，旧的划掉不删 |
| `SESSIONS.md` | 一个 session | 只追加，存原话 |
| `LOG.md` | 一次学习 | 只追加 + `×N` 频次 |
| `BOUNDARIES.md` | 一条线 | 会改，改动次数 git 自算 |

### 4.1 只写不可重导的三样

我以为什么结果错了 · 我否掉了什么 · 我为什么把线画在这里。**其余一律不写。**

### 4.2 唯一的管理动作 【假设】

写 LOG 前 grep 一下：像以前写过的就 `×N +1` 并追 session id，不像才新起。

**赌注**：`×N` 在 200 条时的信号会比 20 条时更清晰。若规模上去反而糊了
（同一件事三种措辞、grep 撞不上、`×N` 永远停在 1），**整套价值塌一半，而且是静默地塌**。

### 4.3 不要做的三件

建分类体系（写时要判断，且三个月就漂）· 定期整理（打卡，第十轮会停）·
周期性总结（总结是回忆，回忆是空的）。**凡是为了整洁而付出的，都会死。**

## 5 · 拦截：怎么保证拦得住

**先翻译**：状态流转 = 一次写操作。所以拦的不是模型的行为，是那条写路径——而写路径是代码。
模型可以在对话里说"我们进 build 了"，但**文件不变，状态就没变**。

| # | 拦什么 | 怎么拦 | 硬度 | Codex | 标签 |
|---|---|---|---|---|---|
| 5.1 | 状态被改成不该有的样子 | 工具是唯一写路径 | 完全 | ✓ | 【推理】 |
| 5.2 | 条件不满足就推进 | **elicitation required 字段** | 完全 | ✓ | 【实测】 |
| 5.3 | 不 begin 就干活 | 后续工具没 token 全拒 | 较硬 | ✓ | 【推理】 |
| 5.4 | Bash 绕过直接改文件 | PreToolUse deny | 完全 | ✗ | 【实测】 |
| 5.5 | 什么都不做 | —— | **拦不住** | —— | —— |

### 5.6 为什么这个强度够了 【推理】

**你防的是「顺手绕过」，不是「蓄意攻击」。**模型不想骗你，它想帮你，所以可能"体贴地"跳一步。
对付顺手，任何摩擦都够。标准是：**没有一条路是「不知不觉就走了」的。**

### 5.7 5.5 那个洞怎么办

拦不住，但**可检测**：下一个 session 一 begin，就告诉你上一个没归档。
**沉默的漏才是真漏；这个漏会在下次开工时撞你脸上。**

### 5.8 别用提示词 / Skill 守门

它失败的方式很糟：模型会说服自己这不算冲突、或者拒绝一次你一推就从、或者照做且不提。
**三种你都看不出来。**Skill 只配讲格式，不配讲时机。

## 6 · 面板：未读变更监控

### 6.1 它是什么——一句话

> **把 git 的「什么变了」，翻译成「什么变了、而且你还没消化」。**

**别再加别的。**加了就开始跟 git、编辑器、Claude Code 抢活，而那三个都比你强。

### 6.2 凭什么不是 git diff 的丑包装 【推理】

四条，git 结构上都给不了：

1. **相对「你上次看过」的 diff**，不是相对上次 commit —— git 不记录你看没看过
2. **按你的档案结构分类**（边界动了 / 上游产物动了 / 判据单改了），不是按目录
3. **传播** —— Spec 动了 → Arch 结论变可疑。git 只看文件不看依赖
4. **未读标记**

「未读」是唯一的新原语，2/3/4 都是它的推论。

### 6.3 它为什么该第一个做 【推理】

**它不依赖方法论。**零方法论、第一天就有用，只要 git 加一个"上次看到哪"的游标。
推论：采用门槛最低 · 其余全失败它也独立成立 · **可以在手跑 session 之前就用上**。

### 6.4 退化判据

**如果你开始用它看具体代码 diff，就退化了。**它只该告诉你「去看哪个」，
看本身在终端 / 编辑器 / Claude Code 里。想加语法高亮、行内 diff、评论时——停。

### 6.5 版式

已落 `src/web/status.html`（215 行，800px 下实测渲染正常）。
主屏是**新鲜度图不是环**——阶段已不流转，在变的是「哪些结论还可信」。
沿用 panel.html 的视觉语言，守 2026-07-29 那四条（颜色不是唯一信号 / 禁高饱和 / 方向是减）。

**注**：那份还叫「状态流转」，按 §6.1 它该改叫「未读」。版式不用大动，语义要改。

## 7 · 命令行

```bash
sp status              # 资产 + 数（日常看）
sp check [--stage X]   # 体检，非零退出（钩子调 + 推进前调）
sp close               # 收尾归档（唯一有写入的）
sp find <词>           # 取回
```

### 7.1 抄 git 的不是子命令形状，是**可组合**

exit code 有意义 · 一行一条 · **没问题就不说话**（每次刷屏的检查，第十次就被无视）。

### 7.2 输出同时喂三个读者

人、模型、钩子。所以：`LEVEL | 位置 | 说的什么`，exit code 反映最高等级。
不要 JSON 刷屏（人读不下去），不要散文（模型解析不稳）。

### 7.3 `sp find` 可能是四个里最值钱的

因为**取回是整套东西唯一的验收方式**。它把四步折叠成一条：
`grep LOG → session id → 原话 + 前后几条 → git log`。

## 8 · 双端适配

**承重的部分完全不碰客户端**——四份 markdown 和 git 两边一模一样，`sp` 是纯函数。

| | Claude Code | Codex |
|---|---|---|
| MCP / session id / elicitation | ✓ | ✓ |
| **可编程钩子** | ✓【实测】 | **没有【推理，值得去验】** |

**原则：承重的建在公分母（MCP + elicitation）上，钩子当增强不当地基。**

收尾触发：CC 用 Stop 钩子；Codex 用"下一个 session 开头补查"。**同一个脚本，两个触发器。**

### 8.1 一个补不了的取舍

Codex 侧互盲只能事后检测。两个选择都合理：接受它弱一档，或者
**按能力分工**——需要严格互盲的工作放 CC，其余随便。互盲是稀有场合，不是日常。

## 9 · 建造顺序

```
1. 未读变更监控        零依赖，day one 有用，最小
2. 手跑 5 个 session   纯文件纯 git，什么工具都不建
3. 还在跑 → 建其余     sp close / MCP 工具 / elicitation 闸
```

**1 不是为 3 铺路，1 自己就成立。**就算第 2 步证明你不会坚持，第 1 步也没白做。
而且它顺带解决第 2 步没有回报的问题——至少每天打开有东西看。

## 10 · 赌注与风险

按「概率 × 伤害」排。**这三条该是 `BETS.md` 的头三行。**

### 10.1 你会真的用它 【假设 · 高危】

**唯一一个设计解决不了的。**成本即时确定、收益延迟看不见，这是所有个人流程工具的标准死法，
而且死得静默：没有报错，只是有一天你不再打开。

§9 的第 2 步就是为这条设计的实验。

### 10.2 取回真的走得通 【假设 · 高危】

`sp find` 那四步**一次都没实测过**。走不通，前面攒的全部作废。

### 10.3 `×N` 在规模上去后信号更清晰 【假设】

见 §4.2。

### 10.4 体检那六条选对了 【假设 · 低危】

我猜的。错了不致命，浪费一段注意力。

### 10.5 下一个该担心的不是"够不够严"

**越严格越容易被弃用。**每个 required 字段、每次卡片弹出，都在收注意力税。

**加东西之前先问：这一条挡住的错误，我真的犯过吗？**没犯过就先进 `BETS.md`，
等它在 `LOG.md` 上升到 `×2` 再装守卫。

## 11 · 验收判据

三条，都可证伪：

1. **取回走得通** —— 真去查一次半年前的事，四步不断。**这是唯一的验收方式**，
   不是"记得全不全"
2. **5 个 session 之后你还在跑** —— 测 10.1
3. **第五次转向的成本显著低于第一次** —— 测这套方法论本身是不是机制而只是描述

做不到就整份打回，别打补丁。
